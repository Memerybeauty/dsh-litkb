## 一、一页结论

1. **交付不是「代码能跑」，是「别人能独立装、独立恢复、独立排障」**。所以做了四件事：安装器、备份恢复、关于与诊断、5 步上手。
2. **安装是一条命令**：`npm run plugin:install -- --profile desktop`；写入 profile、补 bundle、`pnpm install`，失败自动还原。
3. **装完必须完全退出宿主再启动**，再强刷；只刷新页面不会注册新路由——404 先怀疑旧进程。
4. **备份是本地 zip，恢复有安全顺序**：校验 → staging → 快照 → 逐目录替换 → 失败回滚；令牌与缓存永不进备份。
5. **上手按真实库打勾**：导入论文 → 七段卡 → 证据链 → 研究 → 文稿；完成即隐藏，不打扰长期用户。
6. **发布有清单**：verify + coverage + 三处版本 + 打包 + tag + Release + 冷启动复核；回滚分代码与数据两层。
7. **运维的第一性问题是「版本对不对」**：`/health`、关于页、页脚三处版本一致，才能确认新代码真的生效。

## 二、交付形态

| 项 | 内容 |
|---|---|
| 包 | `dsh-litkb-<version>.tgz`（约 5MB） |
| 安装目标 | `~/.dsh/profiles/<profile>`（默认 desktop） |
| 安装方式 | tgz（稳定）或 `link:`（开发） |
| 数据 | 默认 `~/Documents/文献库`，`LITKB_LIBRARY` 覆盖 |
| 卸载 | `pnpm remove dsh-litkb` + 重启；数据目录不自动删 |

### 2.1 安装器做了什么

```text
读 package.json 版本 → 找 tgz（没有就 npm pack）
  → 定位 profile/package.json
  → 写入 dependencies["dsh-litkb"] = file:<tgz 绝对路径>
  → 确保 dsh.profile.bundles 含 dsh-litkb
  → 备份原 manifest 为 package.json.bak-litkb
  → pnpm install --prefer-offline
  → 失败自动还原
  → 打印重启与健康检查步骤
```

参数：`--profile`、`--tgz`、`--link`、`--dry-run`、`--pnpm`、`--skip-install`。

## 三、安装 / 升级 / 卸载

### 3.1 安装

```bash
npm run plugin:install -- --profile desktop
# 完全退出 DSH（不是关窗口）→ 重新启动 → Cmd+Shift+R
curl http://127.0.0.1:<端口>/api/litkb/health   # version 必须等于新版本
```

### 3.2 升级

1. **先备份**（设置 → 数据与备份 → 下载整库备份）；
2. 拉新代码/新 tgz；
3. `npm run build && npm run verify`（源码安装）；
4. `npm run plugin:install -- --profile desktop`；
5. 完全重启 + 强刷；
6. 检查 `/health`、关于页、页脚版本；
7. 抽查：论文列表、卡片、链、研究、文稿各开一条。

### 3.3 卸载

```bash
cd ~/.dsh/profiles/desktop && pnpm remove dsh-litkb
# 重启；数据目录不会自动删除
```

### 3.4 升级/卸载的边界

- 升级不改写库结构；`index.jsonl` 读取时兼容旧字段；
- 卸载不删数据；删库是另一个显式动作；
- 跨大版本升级前必须备份（本项目 v0.11 起支持整库备份）。

## 四、备份与恢复

### 4.1 范围

| 包含 | 不包含 |
|---|---|
| `papers/`、`text/`、`blocks/` | `settings.json`（令牌） |
| `cards/`（含 `.versions/`） | `cache/`（页图、检索历史、任务快照） |
| `translations/`、`deepread/` | `node_modules/` |
| `chains/`、`themes/`、`drafts/` | |
| `concepts/`、`exports/` | |
| `index.jsonl`、`tags.json`、`glossary.json`、`topics.json` | |

zip 根目录带 `manifest.json`：app、kind、version、createdAt、roots、files、bytes、excluded。

### 4.2 恢复安全顺序

```text
校验 zip（格式/大小）
  → 校验 manifest.app/kind
  → 逐条校验路径（拒绝绝对路径、..、空段）
  → 解压到 .litkb-restore-staging-<pid>
  → 当前库快照到 cache/backups/pre-restore-<时间>.zip
  → 逐目录替换，记录已替换清单
  → 任一步失败：按清单回滚
  → 清理 staging / old
```

限制：包 ≤ 512MB、解压 ≤ 2GB、恢复中 409、错误码 428/413/422。

### 4.3 语义

- 备份里有的目录整体替换；没有的目录保留（不凭空删除）；
- `settings.json` 与 `cache/` 永不被恢复覆盖；
- 不做文件级 merge；
- 快照不自动清理，需要时手动删。

## 五、上手与引导

### 5.1 五步

| 步骤 | 判定 | 点击去向 |
|---|---|---|
| 导入第一篇论文 | `index.jsonl` 行数 > 0 | 文件选择器 |
| 生成七段卡 | 有 card 摘要的行数 > 0 | 论文库 |
| 建一条证据链 | 已确认链 > 0（草稿不算） | 论文库 / 审核 |
| 建一个研究并探索 | `themes/*.json` > 0 | 新建研究 |
| 写一份文稿 | `drafts/*.md` > 0 | 写作 |

### 5.2 形态

| 条件 | 形态 |
|---|---|
| 空库 | 欢迎页（大卡 + 三步 CTA + 五步清单） |
| 有数据未完成 | 进度条 `n/5` + 下一步高亮 |
| 全部完成/已隐藏 | 不渲染 |
| 设置里重新显示 | 显示 `5/5`，关闭后隐藏 |

- 「不再显示」写 `localStorage["litkb.guide.dismissed"]="1"`；
- 设置 →「重新显示上手引导」清标记并广播，工作台立即恢复。

## 六、关于与诊断

| 入口 | 内容 |
|---|---|
| 关于 | 版本、Node/平台、数据体积、本地优先说明、复制诊断信息、项目/文档链接 |

## 七、发布流程

### 7.1 清单

- [ ] `npm run verify` 全绿；
- [ ] `npm run coverage` 达标；
- [ ] 三处版本号一致（package / lock / plugin manifest）；
- [ ] README、文档索引、关于页、页脚版本一致；
- [ ] CHANGELOG 有本版条目（用户视角）；
- [ ] tgz 能装、能卸、能回滚；
- [ ] 干净环境冷启动通过；
- [ ] 备份/恢复演练通过；
- [ ] 已知问题清单更新。

### 7.2 命令

```bash
npm version 0.13.0 --no-git-tag-version   # 同步改 dsh.plugin.json
npm run build && npm run verify && npm run coverage
npm pack                                  # → dsh-litkb-0.13.0.tgz
git add -A && git commit -m "release: v0.13.0"
git tag -a v0.13.0 -m "dsh-litkb v0.13.0"
git push origin main && git push origin v0.13.0
gh release create v0.13.0 dsh-litkb-0.13.0.tgz --title "dsh-litkb v0.13.0" --notes-file CHANGELOG.md
```

### 7.3 发布后复核（15 分钟）

1. 干净 profile 用发布包安装；
2. 完全重启 + 强刷；
3. `/health` 版本正确；
4. 主路径点 3 条；
5. 记录安装耗时与异常。

## 八、回滚

| 层 | 方式 |
|---|---|
| 代码 | `git checkout <上一版 tag>` 或安装上一版 tgz，重启 |
| 数据 | 设置 → 从备份恢复；恢复前自动再快照 |
| 配置 | 安装器生成的 `package.json.bak-litkb` |

> 发布前必须确认「上一版能装、上一版备份能恢复」；只备份不演练等于没备份。

## 九、运维与排障

| 现象 | 首先怀疑 | 处理 |
|---|---|---|
| 新接口 404 | 旧进程 | 完全退出重启，不是刷新页面 |
| 前端还是旧界面 | 缓存 | `Cmd+Shift+R` |
| 版本不对 | 装到了别的 profile | 查 `/health` 与 profile manifest |
| 恢复失败 | zip 结构/路径/体积 | 看错误码 428/413/422；查 manifest |
| 数据“消失” | 库路径被覆盖 | 查 `LITKB_LIBRARY` 与设置；从备份恢复 |
| 插件冲突 | bundle 未启用 | 查 `dsh.profile.bundles` |

## 十一、边界

| 项 | 现状 |
|---|---|
| 云同步/定时备份 | 不做；手动 zip |
| 多用户/权限 | 单机单用户 |
| 备份加密 | 不做；zip 明文 |
| 自动更新 | 不做；安装器 + 重启 |
| 令牌迁移 | `settings.json` 不进备份，换机重填 |

---

## 十二、结论

交付的关键不是「功能列全」，是**把不可控因素关进流程**：
一条安装命令、一次完全重启、一个版本校验、一份自动快照、一张发布清单。
这些做到之后，用户才敢把三年的文献放进来。
