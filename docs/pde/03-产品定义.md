---

## 一、一页结论

1. **一句话**：把论文变成「可定位的证据」，把证据连成「可审核的论证链」，再让链直接进入写作。
2. **它不是阅读器，是证据工作台。** 阅读只是入口；产品的价值发生在「读完之后的三个月」。
3. **五条原则**：证据可溯、受控生长、失败显式、人审闭环、本地优先。每条都能在代码里找到对应约束。
4. **核心模型只有七个对象**：论文、卡片、块、证据、链、研究、文稿。对象之间的关系比功能数量重要。
5. **范围克制到一条主链路**：收文 → 解析 → 卡片/精读 → 建链 → 研究 → 写作。其他都是支线。
6. **六个取舍决定了产品形态**：自动建链只出草稿、概念图谱先隐藏、界面单页化、数据本地化、建链证据优先、写作不自动成文。

---

## 二、定位

### 2.1 一句话

> 装进 DeepSeek Harness 的本地文献知识库：收文 → 精读/七段卡 → 证据链 → 横向对比/图谱 → 可追溯问答 → 写作。

### 2.2 电梯演讲

> 你读过的论文，大部分在三个月后只剩一个文件名。
> 文献工作台把每篇论文拆成带页码的引文块，把你的判断连成可审核的证据链；写作时每条结论都能跳回原文。
> 数据全部在本机，不上传整库；没有证据的结论，产品不让你写进稿子。

### 2.3 与「AI 读论文」的区别

| 维度 | 聊天式 AI | 本产品 |
|---|---|---|
| 输出 | 一段回答 | 可定位的证据块 + 链 |
| 可信 | 靠模型自觉 | 强制 q-id + 页码 + 校验 |
| 积累 | 对话即焚 | 库越用越厚 |
| 写作 | 复制粘贴 | 引用/参考文献/反链 |
| 数据 | 上传 | 本地 |

## 三、五条产品原则

| # | 原则 | 含义 | 代码/设计里的体现 |
|---|---|---|---|
| P1 | **证据可溯** | 没有库内 q-id 的结论不许进稿 | 链节点必须带 q-id；答案校验引用；无证据时降级为抽取式 |
| P2 | **受控生长** | 概念、类目、研究细分不自由膨胀 | 受控词表 + 待归一队列 + 细分由人定义 |
| P3 | **失败显式** | 失败必须有原因、有落点、可重试 | 导入失败分类、任务失败明细、断链提示、解析质量分 |
| P4 | **人审闭环** | 自动产出只是草稿，确认后才生效 | 自动建链 draft + 审核队列；主题建链同样审核 |
| P5 | **本地优先** | 资产在本机，最小外发 | 库是文件夹；备份是本地 zip；只发必要文本给模型 |

> 这五条不是价值观口号，是**验收项**：任何改动如果破坏其中一条，即使功能更好用也不合入。

## 四、概念模型

### 4.1 七个对象

| 对象 | 是什么 | 关键字段 | 生命周期 |
|---|---|---|---|
| **Paper** | 一篇论文 | id、title、authors、year、doi、tags、sha256 | 导入 → 解析 → 卡片 → 精读 |
| **Card** | 七段式结构化摘要 | 七段文本、状态、版本、批注 | 生成 → 编辑 → 重生成 → 回滚 |
| **Block** | 版面块（原文的最小单位） | page、bbox、text、order | 解析产出，可重建 |
| **Evidence** | 可引用的证据（q-id） | quote、page、blockId、kind | 选区/批注/卡片生成，可复用 |
| **Chain** | 论证链 | claim、nodes[]、relation、status | 草稿 → 已确认 → 合并/失效 |
| **Theme** | 一个研究 | 细分描述、论文集、结论、文稿绑定 | 新建 → 匹配 → 建链 → 结论 |
| **Draft** | 文稿 | 正文、引用、参考文献 | 新建 → 编辑 → 导出 |

### 4.2 关系

```text
Paper 1─n Block 1─n Evidence(q-id)
  │                    │
  │ 1─1 Card           │ n
  │                    ▼
  └──────────────▶ Chain(claim + nodes)
                       ▲
Theme 1─n Facet ───────┘（每个细分一条主链）
  │
  └─1─n Draft（引用链/证据）
```

**关键约束**：

- 链的节点只能来自库内证据（q-id），不能是自由文本；
- 一个细分只保留一条 confirmed 主链，补充草稿并回主链（v0.6.0）；
- 文稿引用解析到 q-id，参考文献由库生成，不手抄。

| 证据 | q-id、bbox、上下文、断链修复、JSON/CSV | ✅ |
| 建链 | 四种手动建链、单篇自动草稿、跨论文对比/矛盾、主题建链 | ✅ |
| 研究 | 细分、匹配、覆盖矩阵、结论 basis、过期提示 | ✅ |
| 图谱 | 证据链知识库（Cytoscape）、布局持久化 | ✅ |
| 检索问答 | BM25、链优先答案、q-id 校验、历史 | ✅ |

| Agent | 12 个 `lit_*` 工具，写操作需 `confirm:true` | ✅ |
| 产品化 | 上手、备份恢复、诊断、安装器 | ✅ |
| 数据生命周期 | 删除论文（影响面 + 二次确认 + 链/研究同步） | ✅ v0.13.0 |

### 5.2 第一版不做

| 不做 | 原因 |
|---|---|
| PDF 阅读器/编辑器 | 宿主与系统已有 |
| 团队协作/共享库 | 权限与审计是另一个产品 |
| 云同步/账号 | 隐私、成本、合规 |
| 全自动写综述 | 可信度不足，先做提纲 + 引用 |
| 向量检索/LLM 重排 | 百篇级 BM25 够用 |
| 移动端 | 精读与写作在桌面 |

### 5.3 延后（有数据/接口，无入口）

- 概念图谱 UI（数据、接口、组件都在，入口隐藏）；
- 文件夹监控、导入队列取消；
- 定时备份、云同步、备份加密；
- 多分辨率截图矩阵与触屏适配。

## 六、六个关键取舍

| # | 取舍 | 选项 | 决定 | 放弃了什么 | 依据 |
|---|---|---|---|---|---|
| D1 | **自动建链** | 直接进正式库 vs 草稿 + 审核 | 草稿 + 审核 | 「一键生成整库图谱」的爽感 | 错链污染检索与图谱，修复成本远高于审核成本 |
| D2 | **图谱** | 概念图谱 vs 证据链图 | 先证据链图，概念图隐藏 | 概念网络的可视化叙事 | 没有证据的图是装饰；概念图数据保留，等产品决定 |
| D3 | **界面** | 多页导航 vs 单页大卡片 | 单页 + 二级视图 | 传统后台的「功能菜单」 | 研究是连续动作，切页会丢上下文 |
| D4 | **数据** | 云端同步 vs 本地库 | 本地文件夹 + 手动备份 | 多端实时同步 | 隐私、离线、可迁移优先 |
| D5 | **建链** | 先立论点再找证据 vs 证据优先 | 证据优先（v0.9.0） | 「先写观点」的顺畅感 | 选中句必须是证据，不能当论点；否则链从源头就不可信 |
| D6 | **写作** | 自动生成全文 vs 提纲 + 引用 | 提纲 + 引用 + 按证据扩写 | 一键成稿 | 学术写作的责任在人；产品只保证「每句有出处」 |

### 6.1 取舍的代价（诚实版）

- D1：自动建链的召回被审核卡住，用户必须点「确认」；换来的是检索/图谱不被污染。
- D2：概念图谱隐藏后，跨领域的「概念相似」不可见；换来的是每张图都能落到证据。
- D3：单页结构在功能变多后变长；换来的是研究流程不被打断。
- D4：没有云同步，换机靠 zip；换来的是数据主权与离线可用。
- D5：证据优先让「先有观点」的建链多一步；换来的是节点天然可溯。
- D6：不自动成文，写作仍要人组织；换来的是引用与论证一致。

## 七、差异化定位

```text
                写作闭环强
                     ▲
        Zotero       │        本产品
     （管条目）       │     （证据 → 链 → 稿）
                     │
   ──────────────────┼──────────────────▶ 证据可溯强
                     │
      ChatPDF        │   Obsidian + 插件
   （单篇问答）       │   （笔记 + 块引用）
                     │
                写作闭环弱
```

- **右上角是空白**：既强证据、又接写作的产品几乎没有；
- Zotero 强在管理，弱在论证；Obsidian 强在自由，弱在约束；ChatPDF 强在即时，弱在可信；
- 本产品用「q-id + 链 + 引用」占住右上角，代价是学习成本与前期配置。

## 八、成功指标

### 8.1 北极星

> **有 confirmed 链覆盖的细分比例**（研究的「论证完成度」）。
> 它同时反映：收文够不够、精读有没有用、建链顺不顺、研究是否真的在推进。

### 8.2 指标与护栏

| 类型 | 指标 | 目标 | 当前（4 篇库） |
|---|---|---|---|
| 价值 | 细分覆盖率 | ≥ 80% | 72%（13/18） |
| 信任 | 证据可定位率 | ≥ 98% | 100%（61/61，修复后） |
| 质量 | 链 precision（人工 1–5） | ≥ 3.5 | 未测（30 篇评估待做） |
| 质量 | 结论 groundedness | ≥ 3.5 | 未测 |
| 效率 | 单篇处理 | ≤ 3 分钟 | 未系统计时 |
| 护栏 | 导入失败可解释率 | 100% | ✅（失败分类） |
| 护栏 | 自动链错链率 | 越低越好 | 未统计（审核队列有数据） |
| 护栏 | 数据可恢复 | 100% | ✅（备份 + 快照） |

> 指标只列能算的；「用户满意度」这类没有测量的，不放进表里充数。

## 九、结论

产品定义的核心不是「功能多」，而是**一条可信的主链路 + 六个想清楚的取舍**。
这条链路已经跑通（见 `04`），但价值指标只在小样本上验证（72% 覆盖、100% 可定位）；能否在 30 篇真实库上成立，是 `10` 里的 P0。
