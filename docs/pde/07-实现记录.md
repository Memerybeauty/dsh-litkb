## 一、一页结论

1. **6 天不是均匀推进，是「先打通、再收口」**：第 1 天装得上 + 收文，第 2 天从卡片做到知识库图，第 3 天场景补齐 + 文档，第 4 天研究工作台与 UI 收敛，第 5 天产品化，第 6 天自动管线。
2. **小步是真的小步**：40+ 个版本、每个都有 CHANGELOG 与可安装包；v0.2.x 一天发了 14 个版本，每个都能回滚。
3. **关键实现都围绕「证据」**：段落重建让证据能跨块/跨页定位；证据优先让选区先落 q-id；链生命周期让一细分只有一条主链。
4. **工程化是中途补的，不是一开始就有**：v0.2.13 才接 ESLint/CI/覆盖率，v0.2.14 才 0 warning + Prettier；补完之后返工明显变少。
5. **返工集中在 UI**：抽屉定位、类名冲突、双入口不一致、图谱高度——四个都不是业务逻辑错，是「界面结构」错。
6. **实现顺序有一条隐含纪律**：先让数据对（解析/块/证据），再让交互顺（建链/审核），最后让界面稳（令牌/布局/回归）。

## 四、五个关键实现

### 4.1 段落重建（v0.4.0）

**问题**：PDF 按块解析，一句话被切成三块、跨页断开；证据只能定位到块，读起来断点。
**做法**：按阅读顺序合并跨块/跨页续句；双栏整宽块分隔，栏内先左后右；段落作为证据匹配单位。
**结果**：解析稿无断点；证据可按段落匹配；点击定位整段高亮（v0.4.2/0.4.4）。

### 4.2 证据优先建链（v0.9.0）

**问题**：选区建链把选中句当论点，用户需要「先写观点再找证据」，链从源头不可信。
**做法**：选中句先落 `kind=selection` 证据（q-id + page + block），再带着证据开链编辑器；论点由证据反推、可改。
**结果**：同句同页复用同一条证据；卡片页只保留追问（卡片文本不是原文）；v0.9.1 补上解析页入口。

### 4.3 链生命周期与去重（v0.6.0）

**问题**：同一细分有多条 confirmed 链，检索/图谱重复。
**做法**：一细分一主链；补充草稿确认时把节点并回主链并删草稿；提供 `chains/dedupe` 合并历史重复，保留最早一条。
**结果**：POC 的 5 个重复组有了处理入口；图谱与检索不再被重复链污染。

### 4.4 备份与恢复（v0.11.0）

**问题**：库是文件夹，换机/升级/误删没有安全网。
**做法**：整库 zip + manifest；排除令牌与缓存；恢复前校验路径、staging、快照当前库、逐目录替换、失败按清单回滚。
**结果**：包 ≤ 512MB、解压 ≤ 2GB、并发 409；空库恢复演练通过。

### 4.5 入库自动管线（v0.12.0）

**问题**：导入后用户还要手动点解析、卡片、精读，首次体验断成三截。
**做法**：导入成功即后台串行解析→卡片→精读；进度条显示步骤/跳过/失败；已有产物跳过；无模型时只解析并标记跳过。
**结果**：首次导入即完成主要处理；「补全」入口兜底；任务失败有明细。

## 八、提交与发布纪律

- 一个提交一件事；`feat:` / `fix:` / `docs:` / `chore:` / `release:`；标题带版本；
- 每个交付版本打 tag（v0.1.0 / v0.1.1 / v0.1.2 / v0.11.0 / v0.11.1 / v0.12.0 / v0.13.0）；
- 发布前 `npm run verify` + `coverage` + 装机冷启动；
- 版本号三处同步（package / lock / plugin manifest）；
- 生成物 `lib/` 不手改，改 `src/`。

## 九、结论

6 天能做出这个规模，靠的不是「写得快」，是**每一步都可安装、可回滚、可验证**：
40+ 个版本把返工切成小段，工程化把 UI 错误变成断言，证据优先把产品原则写进了代码路径。
