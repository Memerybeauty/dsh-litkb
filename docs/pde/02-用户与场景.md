## 一、一页结论

1. **目标用户是「一个人写一篇东西」的研究者**：研究生、青年教师、企业研究岗；单机、中文优先、没有团队协作诉求。
2. **三个高频场景**：收文归档、精读建链、综述写作。三者共享同一份证据库，不是三个独立功能。
3. **场景的成功标准必须是「点得出来」的**：能不能在 3 分钟内找到那句话、能不能一键插进稿子、换机后数据还在不在。
4. **最容易被忽略的场景是「三个月后回来」**：不是第一次读，而是半年后写东西时还能不能接上。产品的结构（q-id、链、研究）都是为这个场景服务的。
5. **非目标同样明确**：不做团队共享库、不做移动端、不做「帮我读完所有论文」的全自动代理。

## 二、目标用户

### 2.1 画像（假设，待访谈验证）

| 维度 | 描述 |
|---|---|
| 身份 | 计算机/医学/社科方向的研究生或青年研究者 |
| 任务 | 开题、综述、论文相关工作；一年 3–5 个写作任务 |
| 文献量 | 一个主题 20–60 篇，长期积累 100–300 篇 |
| 工具 | Zotero/EndNote + PDF 阅读器 + Word/LaTeX + 笔记软件 |
| 能力 | 愿意折腾工具，但不写代码；能接受「先配置一次」 |
| 痛点 | 读完就忘、找不到出处、引用与论证脱节、换机丢数据 |
| 反感冒犯 | 整库上传云端、AI 编造引用、被强制改变写作习惯 |

### 2.2 使用环境

- macOS 桌面端为主，DSH 作为宿主；
- 中文论文占比高，扫描件/双栏 PDF 常见；
- 网络可用但不稳定，模型调用按次计费；
- 数据敏感：未发表想法、审稿意见、合作方材料。

## 三、三个高频场景

### 场景 A · 收文与归档

| 项 | 内容 |
|---|---|
| 触发 | 找到一篇新论文（下载 PDF / DOI / arXiv） |
| 步骤 | 拖入 → 去重 → 抽元数据 → 分类打标 → 解析 → 建卡片 → 自动精读 |
| 成功标准 | 1 分钟内入库；重复文件不产生第二条；解析失败有原因、可重试；下次能找到 |
| 失败表现 | 静默失败、重复条目、分类空白、解析质量差但无提示 |
| 对应能力 | 拖拽/多选、sha256 去重、DOI/arXiv 导入、自动管线、失败面板 |

### 场景 B · 精读与建链

| 项 | 内容 |
|---|---|
| 触发 | 需要判断「这篇到底说了什么、能不能支撑我的观点」 |
| 步骤 | 打开七段卡 → 精读 11 板块 → 在原文解析里选句 → 建链 → 补证据 → 审核 |
| 成功标准 | 10 分钟看懂；每条结论能跳到页码；选中的句子成为证据而不是论点；链可重开、可插入文稿 |
| 失败表现 | 卡片是空话、页码对不上、选区建链把句子当论点、链保存后找不到 |
| 对应能力 | 七段卡、精读、q-id、bbox 高亮、证据优先建链、链编辑器、审核队列 |

### 场景 C · 综述写作

| 项 | 内容 |
|---|---|
| 触发 | 要写综述/开题/方法对比，需要把多篇的结论组织起来 |
| 步骤 | 建研究 → 拆细分描述 → 匹配论文 → 主题建链 → 审核 → 生成结论 → 插入文稿 → 参考文献 |
| 成功标准 | 每个细分都有链；结论能回到链；引用一键插入；参考文献格式正确；过期结论有提示 |
| 失败表现 | 匹配不切题、链重复、结论无支撑、插入后引用丢失 |
| 对应能力 | 研究工作台、细分匹配、主题建链、覆盖矩阵、结论 basis、写作引用 |

### 3.1 三个场景的关系

```text
        ┌──────────────┐
        │  A 收文归档   │  输入
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  B 精读建链   │  理解 + 证据
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  C 综述写作   │  复用 + 输出
        └──────────────┘
               │
               └──▶ 新文献回到 A（循环）
```

**关键**：A/B/C 共用同一份 `papers / cards / blocks / chains / themes / drafts`，不是三个数据库。这是产品能「越用越值钱」的前提。

## 四、JTBD（Jobs To Be Done）

| # | 当…… | 我想…… | 这样我就能…… |
|---|---|---|---|
| J1 | 我下载了一篇新论文 | 一分钟内放进库里并知道它属于哪类 | 不用维护文件夹 |
| J2 | 我要判断一篇论文值不值得读 | 10 分钟看到结构化摘要和关键证据 | 决定精读还是放弃 |
| J3 | 我要引用一句话 | 点一下跳到原文并拿到可引用的块 | 不抄错、不编造 |

| J6 | 我换电脑/升级 | 整库备份、恢复后一切还在 | 敢长期投入 |

## 六、关键假设与验证状态

| # | 假设 | 证据 | 状态 |
|---|---|---|---|
| H1 | 用户愿意为「可追溯」多花时间 | 只有本人使用；无对照 | ❌ 未验证 |

| H3 | 自动建链必须人工审核 | 草稿 + 审核上线；审核面板有「确认/拒绝/编辑」 | ✅ 方向验证 |

## 七、非目标用户

| 非目标 | 原因 |
|---|---|
| 团队/实验室共享库 | 权限、并发、审计是另一个产品 |
| 纯移动端用户 | 写作与精读在桌面完成 |
| 「帮我读完所有论文」的全自动用户 | 可信度与责任边界不成立 |
| 只想要摘要的轻度用户 | 用聊天式工具更合适，本产品价值在证据 |

## 八、场景走查（v0.6.2 起）

按「论文库 → 横向精读/图谱/检索 → 工作台 → 写作 → 设置」逐块走查，固定 6 项：

1. 入口是否唯一、有没有重复/无效按钮；
2. 空态、加载、错误、长文本、窄屏；
3. 按钮尺寸/文案/危险操作确认；
4. 数据一致性（列表与详情、统计与筛选、导出与当前筛选）；
5. 已知欠账是否仍成立；
6. 术语统一（论文/文献、证据链/论证链、研究/主题）。

**产出**：走查表 + 待定清单。v0.7.x 的「入口收进更多」「导出收进菜单」「DOI 判重」「任务取消/续跑」都来自这张表，不是拍脑袋加的。

## 九、结论

三个场景成立，且共享一份证据库；产品的护城河不在「读」，在「读完之后的证据结构」。
但**用户是否愿意改变习惯**仍未验证——这是本案例最大的未知，也是 `10` 里 P0 事项的由来。
