## 一、一页结论

1. **设计的第一原则是「不打断研究」**：研究是连续动作，切页、弹窗、丢状态都会让人断片，所以界面收敛成「单页大卡片 + 二级视图」。
2. **信息架构只有三块**：个人工作台（研究）、论文库（读与证据）、写作（输出）。三者共享同一份数据，不是三个应用。
3. **证据优先体现在交互里**：在原文里选一句话点「建链」，这句话先成为证据，再带着证据去写论点——而不是反过来。
4. **设计系统不是皮肤，是约束**：最小字号 11px、按钮 32px、8px 网格、圆角 6/10/14、两级阴影、对比度 4.5:1；439 个散落 hex 收敛成令牌。
5. **最贵的 bug 都在「布局与状态」**：高度链、定位祖先、类名冲突、溢出裁切、深底深字。修复都补了回归断言。
6. **视觉证据齐全**：P0–P5 的浅/深色对照、图谱、检索、悬浮框截图都在 `docs/assets/`，可以逐屏对照。

## 二、信息架构

### 2.1 顶层只有三块

```text
文献工作台
├── 个人工作台（默认）
│   ├── 研究卡片（新建 / 模板 / 从标签建）
│   └── 研究页：总览 · 参考论文 · 证据链 · 研究结论
├── 论文库
│   ├── 论文（列表 → 详情：详情 / 七段卡 / 精读 / 原文解析）
│   ├── 横向精读（2–4 篇并排）
│   ├── 图谱（证据链知识库）
│   └── 检索（链优先答案 + 历史）
└── 写作
    ├── 文稿（编辑器 + 引用）
    ├── 引用库
    └── 参考文献
```

### 2.2 为什么这样分

| 分块 | 用户问题 | 设计回答 |
|---|---|---|
| 工作台 | 「我同时在研究什么」 | 研究卡片 + 进度，不进入具体论文 |
| 论文库 | 「这篇/这几篇说了什么」 | 列表 → 详情 → 原文，三层递进 |
| 写作 | 「怎么把结论写成稿」 | 文稿 + 引用 + 参考文献，独立模块 |

**关键**：论文库不负责「研究」，写作不负责「建链」；每个模块只回答一个问题。

### 2.3 页面清单

| 页面 | 核心区域 | 状态设计 |
|---|---|---|
| 工作台 | 研究卡片、进度环、5 步上手 | 空库 → 欢迎页；有数据 → 进度条；完成 → 隐藏 |
| 研究页 | 顶部总览 + 三视图切换 | 加载 / 空研究 / 匹配中 / 任务失败 |
| 论文库列表 | 筛选、KPI、行操作 | 空态 CTA、重复提示、解析质量低提示 |
| 论文详情 | 四页签 + 右栏原文 | 断链提示、partial 标记、删除影响面 |
| 精读 | 11 板块 + 小节导航 | 生成中 / 失败重试 / 逐段编辑 |
| 原文解析 | 段落 + 页图联动 | 块缺失、页码越界、选区工具条 |
| 横向精读 | 2–4 篇并排、差异高亮 | 选择不足、超 4 篇、加载失败 |
| 图谱 | 画布 + 过滤 + 布局 | 空图、单节点、布局保存失败 |
| 检索 | 输入 + 答案 + 引用 | 无结果、无模型降级、引用校验失败 |
| 写作 | 三栏（文稿/引用/参考） | 自动保存、引用失效、导出失败 |
| 设置 | 库/模型/维护/备份/关于 | 备份中、恢复中（409）、校验失败 |

## 三、三条关键流程

### 3.1 收文 → 自动处理（v0.12.0）

```text
拖入 PDF / 粘贴 DOI
  → 去重（sha256 / DOI）
  → 抽元数据 + 分类打标
  → 入库（列表出现）
  → 后台自动：解析 → 七段卡 → 精读
  → 进度条：步骤打勾 / 跳过 / 失败
  → 完成提示 + 列表刷新
```

| 设计点 | 处理 |
|---|---|
| 用户等待 | 先入库再后台处理，不等全流程 |
| 无模型 | 只完成解析，卡片/精读标记「跳过」并说明 |
| 已有产物 | 自动跳过，不重复烧 token |
| 失败 | 单步失败不影响其他步骤；可手动「补全」 |
| 重复 | 提示「已在库中」并可打开已有记录 |

### 3.2 精读 → 证据优先建链

```text
打开原文解析 → 选中一句话
  → 浮动工具条（建链 / 评论 / 追问）
  → 点「建链」：先落 kind=selection 证据（q-id + page + block）
  → 打开链编辑器：自动按证据提论点（可改）
  → 补证据 / 选关系 / 保存草稿
  → 审核队列确认 → 进入图谱与检索
```

| 设计点 | 处理 |
|---|---|
| 选中句的角色 | 永远是证据，不是论点（v0.9.0） |
| 重复建链 | 同句同页复用同一条证据 |
| 卡片页选区 | 只保留「追问」，不做证据锚点（卡片文本不是原文） |
| 工具条位置 | 默认在选区上方，空间不足才落下 |
| 失败 | 无页码/块失效时明确提示，不静默 |

### 3.3 研究 → 探索 → 写作

```text
新建研究（模板 / 标签 / 空白）
  → 定义 4–6 条细分描述
  → 匹配论文（阈值可调、可解释、别名扩展）
  → 主题建链（草稿）→ 审核
  → 覆盖矩阵：哪些细分还没链
  → 生成结论（绑定链，过期提示）
  → 插入文稿 → 参考文献
```

| 设计点 | 处理 |
|---|---|
| 匹配不切题 | 显示打分拆解，可调阈值/别名 |
| 重复链 | 一细分一主链；补充草稿并回；可合并 |
| 结论过期 | 链变化后提示「结论可能过期」，不自动改写 |
| 任务中断 | 主题任务持久化，重启后续跑 |
| 覆盖不足 | 矩阵直接显示缺口，不藏在一堆数字里 |

## 四、设计系统

### 4.1 令牌

- 颜色：语义令牌（text/text-2/text-3/accent/success/warn/danger/surface/border），全部映射宿主 DSH 别名；
- 图谱调色板单独一套（`GRAPH_PALETTE`），深浅两版；
- 439 个散落 hex → 令牌 + 语义色 + 图谱色板；组件里禁止写颜色。

### 4.2 字体阶梯

| 角色 | 字号/行高 | 用途 |
|---|---|---|
| 页面标题 | 20/1.4，600 | 工作区/页面主标题 |
| 区块标题 | 15/1.5，600 | 面板、弹窗标题 |
| 小标题 | 13/1.5，600 | 卡片标题、列表主行 |
| 正文 | 13/1.7 | 卡片正文、精读、解析稿 |
| 辅助 | 12/1.6 | 元信息、按钮、标签 |
| 微型 | 11/1.5 | 页码、计数、脚注 |
| 徽标 | 10.5/1.4，500 | 仅状态/计数，不承载句子 |

**硬规则**：删除 9/9.5px 正文；最小可读 11px；中文字重 400/500/600。

### 4.3 间距、圆角、阴影、动效

- 间距：4 / 8 / 12 / 16 / 24 / 32（8px 网格）；
- 圆角：6（小控件）/ 10（卡片、输入）/ 14（弹窗、面板）；
- 边框：1px；hover 用 border-strong 或 accent 30%；
- 阴影：`shadow-1` 卡片、`shadow-2` 浮层；不做重阴影；
- 动效：120–180ms；不做弹跳/长动画。

### 4.4 组件规格

| 组件 | 规格 |
|---|---|
| Button | primary/ghost/quiet/danger；高 32（默认）/28（工具栏）/24（行内） |
| Input/Select/Textarea | 高 32；focus ring 2px + offset 2px |
| Tabs | 高 32，字号 12，激活下划线 |
| Card | 圆角 10，1px 边框，shadow-1 |
| Drawer | 宽 `min(720px, 100%)`，固定头，内部滚动 |
| Dialog | 圆角 14，shadow-2，遮罩统一 |
| Badge/Pill | 10.5–11px，仅状态/计数 |

### 4.5 可访问性

- 正文对比度 ≥ 4.5:1，大字号 ≥ 3:1，浅/深主题都测；
- 命中区 ≥ 32×32，行内小按钮 ≥ 24×24；
- 焦点态可见（2px ring）；
- 不用颜色单独表意（状态同时有文字/图标）。

## 五、六个设计决策

| # | 决策 | 选项 | 选择 | 放弃 | 依据 |
|---|---|---|---|---|---|
| D1 | **单页结构** | 左侧导航 + 多页 vs 单页大卡片 | 单页 + 二级视图 | 传统后台的菜单层级 | 研究是连续动作，切页丢上下文 |
| D2 | **三栏阅读** | 列表/详情/原文分页 vs 连续三栏 | 列表 + 详情 + 右栏原文 | 大屏信息密度 | 「看卡片时能对照原文」是高频动作 |
| D3 | **证据优先** | 先写论点再找证据 vs 选区先落证据 | 证据优先 | 先表达观点的顺畅 | 节点从源头可溯，避免「论点找证据」 |
| D4 | **抽屉/弹窗** | 全屏页 vs 抽屉 vs 弹窗 | 轻量用抽屉，破坏性用弹窗 | 统一用一种容器 | 阅读上下文不能丢；危险操作要阻断 |
| D5 | **引导** | 一次性教程 vs 常驻进度 | 空库欢迎页 + 5 步进度 + 可关闭 | 强制新手引导 | 按真实库打勾，完成即隐藏 |
| D6 | **主题** | 自建色板 vs 宿主令牌 | 宿主令牌 + 语义色 | 品牌化视觉 | 深浅色自动跟随，减少维护 |

### 5.1 决策的代价

- D1：功能变多后单页变长，靠二级视图与锚点缓解；
- D2：窄屏（<900px）体验下降，未做专项适配；
- D3：建链多一步「先选证据」，对「先有观点」的用户不顺手；
- D4：抽屉与弹窗两套容器，需要统一的定位/滚动规范；
- D5：引导只覆盖 5 步，复杂功能仍需文档；
- D6：视觉个性弱，但换来与宿主一致。

## 六、设计如何落到代码

1. **先立令牌，再改屏**：先把颜色/字号/间距收敛，再逐屏替换，避免一次性改 400+ 颜色回归；
2. **每屏截图对照**：P0–P5 的浅/深截图存放在 `docs/assets/`；
3. **结构断言**：抽屉必须有标题与关闭、图谱必须有高度、下拉必须限高——用测试锁住布局约束；
4. **命名唯一**：组件类名带 `litkb-` 前缀，不复用旧名（v0.8.2 的教训）；
5. **禁止硬编码颜色**：验收时 `grep` hex，发现即改。

## 九、结论与局限

设计上做对的三件事：**单页不打断、证据优先、令牌约束**。
没做的三件事：正式可用性测试、窄屏适配、多分辨率截图矩阵。
设计不是「画得好看」，是让「证据 → 链 → 稿」这条路径上没有一步需要用户猜。
