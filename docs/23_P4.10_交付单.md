## 1. 这次解决了什么

精读解决「这篇论文讲了什么」，写作引用解决「这句话来自哪一页」；
中间缺的是「**我凭什么这么说**」——一句论点，被哪几条证据支持、反驳或限定，能不能直接变成正文。

P4.10 把这条链路打通：

```
精读论点 / 引用库证据 / 研究问题
  → 建链弹窗
  → 用户确认 claim + 节点关系
  → chains/<id>.json
  → 一键插入：带 [[p#^q|作者 年, p.N]] 的论证段
```

### 2.2 数据模型

```json
{
  "id": "c-1a2b3c4d",
  "title": "极坐标变换改善视盘边界",
  "origin": "claim|evidence|question",
  "status": "confirmed",
  "question": "可选",
  "claim": { "text": "…", "paperId": "p-xxx", "sectionKey": "conclusion", "source": "deepread|manual" },
  "nodes": [
    {
      "id": "n-xxxxxxxx", "relation": "supports|contradicts|qualifies|derives|compares",
      "paperId": "p-xxx", "evidenceId": "q-xxxxxxxx",
      "page": 5, "block": "b-xxxxxxxx", "quote": "…", "note": ""
    }
  ],
  "createdAt": "ISO", "updatedAt": "ISO"
}
```

硬约束：

- claim 非空、≤240 字；节点 ≥1、≤12；
- 节点 q-id 必须能在卡片证据里找到；page/block/quote 从卡片复制；
- 非法关系回落 `supports`；重复证据去重；
- 读取时逐节点标记 `stale`（卡片重生成后 q-id 消失）。

### 2.3 四种建链

| 方式 | 实现 | 是否调用模型 |
|---|---|---|
| **论点先行** | 精读结论/创新点/局限/核心要点切句；同句 `[[p#^q]]` + `[p.N]` 同页证据 → 节点；不足时按关键词补 | 否 |
| **证据先行** | 解析选中 q-id；优先找引用这些证据的精读句子当论点 | 有模型才提议；无模型留空 |
| **问题先行** | 复用全库证据检索；英文/数字词权重 4、中文二元组权重 1；按相关度过滤；跨论文每篇最多 2 条 | 有模型才提论点；检索本身不用模型 |
| **原文段落** | 解析稿点正文段 → 首句当 claim 草稿；该段无 q-id 时按段落原文补一条证据（block=该段）；页眉页脚拒绝 | 否 |

AI 只提议：`/chains/propose` 返回 `{claim, nodes, warnings, model}`，不落库；保存必须由用户点「保存链」。

### 2.4 API

| 路由 | 说明 |
|---|---|
| `GET /chains` | 列表（title/claim/nodes/stale/papers/updatedAt） |
| `GET /chains/read?id=` | 单条 + stale 标记 |
| `GET /chains/claims?paperId=` | 精读论点候选 |
| `POST /chains/propose` | 四种方式的候选（不落库；block 模式补证据） |
| `POST /chains/save` | 新建 / 更新；空 claim、无有效节点 → 422 |
| `POST /chains/delete` | 删除 |
| `POST /chains/insert` | 生成带引用的论证段 |

### 2.5 UI

- **精读页底部**「论点与证据链」：列出候选论点（板块标签 + 文本）→「用它建链」；也支持手写一句；
- 精读论点、解析稿段落、右栏证据行、右栏「证据」tab 的「证据链」分段 → 同一 **`ChainDialog` 弹窗**；
- 弹窗不切页签：研究问题 / 论点 / 按论点·问题·已选证据提议 / 节点关系下拉 / 点 p.N 回原文 / 移除 / 备注 / 搜索添加证据；
- 右栏「证据」tab 分两段：「证据 N」逐条可建链；「证据链 N」列出本论文的链（证据数、来源、日期、失效数）；
- 弹窗底部选择目标文稿（或「＋ 新建文稿」）→「插入文稿」服务端追加，自动带引用；
- 写作页不再有证据链 tab 或画布。

## 7. 补丁：原文段落建链（v0.16.1，2026-11-05）

用户提出：**在「原文解析 → 原文」里，随意点一段话，然后建链。**

实现：

- 解析稿每个正文块右侧出现「建链」按钮（悬停或点击聚焦后可见）；
- 点击后取该段首句作为 claim 草稿，并把这一段挂成 `supports` 节点；
- 该段在卡片里还没有 q-id 时，自动补一条证据：引文 = 段落原文，`block` = 该版面块，`page` = 该页；
  这是用户点「建链」的显式动作，不会在浏览时静默写库；
- 重复点同一段复用同一 q-id，不重复建证据；
- 页眉页脚拒绝（`bad_block`），段落太短拒绝（`block_too_short`）；
- `origin` 增加 `block`；仍走 `/chains/propose`，不新增路由；
- 画布提示「已把这一段补为证据 q-xxx（p.N）」，用户可继续加证据、改关系、保存/插入。

验证：`npm test` **87 项全过**；段落建链单测覆盖「补证据 / 复用 / 页眉页脚 / 不存在块」，
路由测试覆盖 `mode=block` 的提议→保存→插入。

## 8. 改造：建链改为弹窗（v0.17.0，2026-11-05）

用户反馈：证据最终应在右栏「证据」tab 里看到；证据链构建要弹窗，不要合并进写作页。

改动：

- 新增 `ChainDialog` 组件（`litkb-chainModal` 遮罩 + `litkb-chainDialog` 面板），Esc/点遮罩关闭；
- 四个入口都打开同一弹窗：
  1. 精读「论点与证据链」→ 用它建链；
  2. 原文解析每段 → 建链；
  3. 右栏「证据」列表 → 每条证据「建链」；
  4. 右栏「证据」tab 的「证据链」分段 → 新建/重开；
- 右栏「证据」tab 增加分段；链列表按论文过滤（`paperIds` / `claimPaperId`）；
- 弹窗底部下拉选文稿，`POST /chains/insert` 增加 `append:true` 与 `draftId`，服务端 `appendChainToDraft` 追加；
- 写作页移除证据链 tab 与链画布；`ChainCanvas` → `ChainDialog`；
- 段落建链补证据后调用 `onEvidenceChanged` → 刷新右栏证据计数。

验证：`npm test` **87 项全过**；路由测试覆盖 `append=true` 新建文稿与追加同一文稿。
