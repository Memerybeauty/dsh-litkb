# 产品定位与场景（v2.0）

> v2 变更：按你给的定义重写。核心从"帮你写"改为"帮你建库"——**论文进来，自动归位、拆成证据、连成图谱**，写作只是下游消费之一。
> 不变的三条：结构化解读、证据链、Obsidian 落地。

---

## 0. 结论先行

| 维度 | 决策 |
|---|---|
| 品类 | 文献知识库（Research Knowledge Base） |
| 一句话 | 一篇论文进来，自动归到位、拆成证据、连成图谱 |
| 主用户 | 手里 50–200 篇 PDF 的研究生（首发：你自己） |
| 载体 | **Obsidian 是前端也是数据库**，Python 是后台工人 |
| P0 场景 | S1 收文归位 + S2 结构化精读 |
| P1 场景 | S3 证据链 + S4 图谱导航 |
| P2 场景 | S5 综述输出 + S6 领域追踪 |
| 明确不做 | PDF 阅读器、通用问答、团队协作（v1）、一键成稿 |

## 1. 定位陈述

> **对于**手里攒了 50–200 篇 PDF 的研究生，
> **他们**苦于"存了找不到、读了连不起来、写了证不实"，
> **本产品**是一个证据优先的文献知识库，
> **不同于** Zotero（只管文件）、Obsidian 原生（全靠手工）、Elicit（一次性问答），
> **它能**自动把论文归类、拆成统一结构的卡片、把每条结论锚到原文页码，并连成可导航的知识图谱。

### 1.1 三条价值支柱

| 支柱 | 一句话 | 凭什么成立 |
|---|---|---|
| **自动归位** | 论文进来就知道放哪、是什么 | 大类（知网 12 类）+ 扁平标签 |
| **结构化拆解** | 每篇都是同一套字段，能横向比 | 七段式卡片 schema，强制具体化 |
| **证据成网** | 每个结论、每条图谱边都有出处 | quote → 页码 → 块 ID，可反查 |

### 1.2 和上一版（v1 写作副驾）的差异

| 维度 | v1 | v2 | 为什么改 |
|---|---|---|---|
| 核心 | 帮你写研究现状 | 帮你把库建起来 | 你要的是"积累与连接"，不是一次成稿 |
| 入口 | 检索优先 | **收文优先**（检索只是补充入口） | 文献主要来自已有库存与新下载 |
| 组织 | 按写作任务临时分组 | **大类与标签 + 图谱**，长期沉淀 | 知识要能复用，不能写完就散 |
| 写作 | 核心场景 | 下游消费（P2） | 库对了，写作是自然结果 |
| 保留 | 证据链、结构化字段、Obsidian 落地 | 同左 | 这三条是你定的方向，不改 |

## 2. 用户与任务

### 2.1 主用户

- **是谁**：研二/研三，医学影像或计算机交叉方向，正在开题或写学位论文；
- **手里有什么**：50–200 篇 PDF（中英混杂）、一个 Obsidian 库、多版开题报告；
- **习惯**：Obsidian 常开、会写 Python、愿意折腾，但没时间维护复杂系统；
- **真实痛点排序**：① 存了找不到 / ② 读了连不起来 / ③ 写了证不实 / ④ 新文献怕漏。

### 2.2 三个 JTBD

1. "当一篇新论文进来时，我想在 5 分钟内知道**它是什么、该放哪、值不值得读**，而不是先存进'待读'文件夹然后忘掉。"
2. "当我要写某段论述时，我想立刻找到**谁说过、在哪一页**，而不是重新翻 30 个 PDF。"
3. "当我要看全貌时，我想知道这个方向的**方法怎么演进、谁和谁可比**，而不是读一堆互不相干的摘要。"

### 2.3 使用情境

- **时间**：组会前、开题前、深夜整理文献时；
- **设备**：Mac + Obsidian，双屏；
- **情绪**：希望"丢进去就不用管"，但不能接受"整理完发现分错了"；
- **容忍度**：可以等 3–5 分钟处理一篇，但不能接受静默失败或编造。

## 3. 场景卡片

### S1 · 收文归位（P0，入口场景）

| 项 | 内容 |
|---|---|
| **触发** | 从 arXiv / ScienceDirect 下了几篇新 PDF，或同门微信发来一篇 |
| **现状** | 丢进 `待读/`，三周后不记得为什么存，文件名还是 `1-s2.0-xxx-main.pdf` |
| **Agent 做** | 5 分钟内：识别身份（DOI/标题）→ 去重 → 补元数据 → **大类与标签** → 生成卡片骨架 → 进"待读" |
| **产出** | `10_论文/<citekey>.md`，总览表自动多一行 |
| **成功标准** | 大类与标签可一键修正；同一篇不产生第二张卡；命名规范化 |
| **失败模式** | 新领域硬塞进旧类目 → 进"待归类"队列，并**建议新类目**等人确认 |
| **频次** | 每周数篇——高频，决定库能不能长大 |

### S2 · 结构化精读（P0，质量场景）

| 项 | 内容 |
|---|---|
| **触发** | 组会要讲这篇，或要判断它能不能当 baseline |
| **现状** | 读摘要和图表 → 读一半放弃 → 三天后忘了它讲了什么 |
| **Agent 做** | 七段式卡片（问题/方法/数据/结果/局限/可引句/与课题关系），引文带页码 |
| **产出** | 卡片正文 + 3–5 条带块 ID 的引文 + 与课题关系判断 |
| **成功标准** | 10 分钟能讲清楚；卡片可直接进综述；"值不值得读"判断与人工一致率 ≥ 80% |
| **失败模式** | 写空话（"提出了一种新方法"）→ 字段模板强制写模块名、数据集、数字 |
| **频次** | 每周数篇 |

### S3 · 证据链（P1，价值场景）

| 项 | 内容 |
|---|---|
| **触发** | 写开题第二章，需要"OC Dice 0.87 以上的有谁、在哪页" |
| **Agent 做** | 在证据库中检索 → 返回"句子 + 页码 + 论文"→ 引用直接落成块引用 |
| **产出** | 草稿中每句可跳原文；反向可查"这条证据被谁用过" |
| **成功标准** | 引用 0 返工；每条引文可展开上下文（前后各一句） |
| **失败模式** | 断章取义 → 强制带上下文窗口，且区分"作者原话"与"我的转述" |
| **频次** | 每次写作 |

### S4 · 图谱导航（P1，全貌场景）

| 项 | 内容 |
|---|---|
| **触发** | 想知道 U-Net 之后这条线怎么演进、谁和谁可比 |
| **Agent 做** | 概念图（方法/数据集/指标）+ 方法演进 Canvas + "可比组"（同数据集同指标） |
| **产出** | `图谱.canvas`、`方法演进.mmd`、可比组表格 |
| **成功标准** | 能看出至少 3 条技术路线；找到 2 个真正可比的基线 |
| **失败模式** | 毛线球 → **只画有证据的边**，默认按主题裁剪，不全量铺开 |
| **频次** | 开题/答辩前集中用 |

### S5 · 综述输出（P2，下游）

- 由卡片与证据自动拼出对比矩阵与分节草稿，每段挂块引用；
- 成功标准：改写率 ≤ 30%，引用可核率 100%；
- 说明：**这是副产品**，不是主战场，别为它牺牲库的质量。

### S6 · 领域追踪（P2，可选）

- 定时检索新文献 → 自动走 S1 流程入库 → 只提醒"影响你对比基线"的；
- 失败模式：变成信息流噪音，三天后就被关掉。

## 4. 优先级

| 场景 | 价值 | 频率 | 难度 | 优先级 | 阶段 |
|---|---|---|---|---|---|
| S1 收文归位 | 5 | 5 | 3 | **P0** | Phase 1 |
| S2 结构化精读 | 5 | 4 | 4 | **P0** | Phase 2 |
| S3 证据链 | 5 | 3 | 3 | P1 | Phase 2–3 |
| S4 图谱导航 | 4 | 2 | 4 | P1 | Phase 3 |
| S5 综述输出 | 4 | 2 | 4 | P2 | 之后（自然产出） |
| S6 领域追踪 | 3 | 4 | 2 | P2 | 之后（可选） |

**逻辑**：S1+S2 是"库有没有价值"的地基，必须先把 30 篇跑通；S3、S4 建立在地基上，是价值放大器；S5 是自然结果；S6 最容易做、也最容易变成噪音，放最后。

## 5. 成功指标

**北极星**：**结构化覆盖率** = 已有卡片且证据 ≥ 3 条的论文 ÷ 库内总论文数，目标 ≥ 90%。

| 护栏指标 | 目标 |
|---|---|
| 大类与标签准确率 | ≥ 90%（抽检 50 篇） |
| 卡片字段完整率 | ≥ 95% |
| 证据可核率 | 100% |
| 图谱边的证据覆盖率 | 100%（无出处的边不画） |
| 单篇处理 | ≤ 3 分钟 / ≤ ¥0.5 |
| 误引事故 | 0 |

## 6. 边界与演进

| 阶段 | 边界 |
|---|---|
| v1 | 只服务你自己；本地；中文优先；眼科/分割领域类目树 |
| v2 | 同门可用：库只读共享、类目树可换 |
| v3 | 若产品化：多用户、云端——**现在不想** |

**三个失败预兆**（出现任一就要回头检查定位）：

1. 类目从 20 个涨到 200 个，没人维护；
2. 图谱节点几百个、边几千条，看不出任何东西；
3. 库里 80% 的论文停在"待读"，卡片覆盖率不涨。

对应三条纪律：**受控词表、只画有证据的边、先跑通 30 篇再扩量**。

---

## 7. 默认设定（有异议再说）

- 主题类目树：我先用你 11 篇核心文献 + 开题报告反推 v0，你改；
- 入口：**手动拖入 + 文件夹监控**，不做浏览器插件；
- 精读界面：就在 Obsidian 卡片里，不另做阅读器；
- 图谱 v1：Obsidian 双链 + Dataview + Canvas，**不上 Neo4j**。
