## 2. 首次启动失败与修复（v0.0.1 → v0.0.2）

**现象**：`web boot: 1 entry did not activate`，`dsh-litkb: failed`。

**根因**：客户端插件必须声明 Cordis 服务依赖 —— 导出 `inject: ['slots']`。
未声明时，`ctx.slots` 在 apply 里解析服务会抛错，插件直接失败。宿主 0.2.x 强制这一约束；0.1.x 没有，所以早前用全局 CLI 测是通的。

**修复**：

```js
return { name: 'dsh-litkb', inject: ['slots'], apply }
```

**教训**：必须用**宿主同版本**验证。全局 `dsh` CLI 是 0.1.1-rc.2，桌面 App 是 0.2.1-rc.5，两者插件 API 不同。现改为用 App 自带的 CLI（`runtime/cli/bin/dsh`，0.2.1-rc.5）+ 无头 Chrome 做端到端回归。

## 5. 重启与回滚

```bash
# 重启：⌘Q 完全退出
# 若入口没出现，先补一次注册（幂等），再打开：
dsh plugin --profile desktop add "link:/Users/memery/Desktop/MEMERY/广西大学/文献研究agent"

# 回滚
dsh plugin --profile desktop remove dsh-litkb
# 再 ⌘Q 重启

# 恢复 profile 备份
cd ~/.dsh/profiles/desktop
cp package.json.bak-litkb package.json
cp cordis.patch.yml.bak-litkb cordis.patch.yml
```
