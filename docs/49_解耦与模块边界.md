# 解耦与模块边界（P0–P3）

> 版本：v0.19.0。目标不是拆微服务，而是让「每个部分能单独改、单独测、单独回滚」。
> 结论先说：路由与存储已经有明确接缝；客户端受宿主限制仍是单文件，但已用显式契约 + CI 校验替代模块边界。

---

## 2. P0：路由按域拆分

| 项 | 改造前 | 改造后 |
|---|---|---|
| 入口 | `apply()` 2,264 行，91 条路由全在里面 | `apply()` **60 行**，只做初始化与装配 |
| 路由组织 | 6 个文件续写同一个函数体 | 6 个 `registerXxxRoutes({ route })` |
| 单域故障 | 抛错即整插件启动失败 | 每域独立 try/catch，记 `route group X skipped` 后继续 |
| 注册器 | 藏在 `apply` 内部 | `05-http.js` 的 `createRouter(webServer)`，统一 405 / 错误码 |

**改一个域时只动一个文件**：加路由就写进对应的 `4x/5x/6x/7x/8x-routes-*.js`，入口不动。

## 3. P1：存储端口

```js
// 默认库（环境变量 LITKB_LIBRARY 优先）
import { PATHS, currentStore, useStore, withStore } from './store.js'

PATHS.papers                    // 当前库的 papers 目录（兼容视图，切换库自动跟随）

const a = createStore('/data/库A')
useStore(a)                     // 之后所有读写都落到库 A
withStore('/data/库B', () => {  // 临时切库，结束自动还原
  readIndex()
})
```

规则：

- 领域模块只 `import { PATHS } from './store.js'`，不再从 `library.js` 拿路径；
- `createStore(root)` 返回冻结的 `{ root, paths }`，路径拼装只有一处；
- 索引缓存 key 带 `root`，切换库不会命中上一个库的缓存；
- **约束**：一个进程同一时刻只有一个活动库；`withStore` 只包同步逻辑，不要跨 `await` 换库。

尚未做：把 `store` 作为参数逐层传入（真正的 per-call 注入）。目前的取舍是「可切换的单例」，
能满足测试隔离、多库切换、将来接远端存储；只有需要同进程并发读写多个库时才值得继续下沉。

## 4. P2：客户端分片契约

客户端受 DSH ModuleLoader 限制必须打成单文件，12 个分片共享一个 factory 闭包。
所以用「显式契约」代替模块系统：

```js
// 00-base.js：共享底座，React / h / api / 格式化工具，各片可裸用
const SHARED = {}

// 40-chain.js 末尾：登记本片对外提供的名字
Object.assign(SHARED, { ChainDialog, Toast, field, metaLine })

// 10-library.js：使用别的分片，一律走 SHARED
h(SHARED.ChainDialog, { ... })
```

| 项 | 改造前 | 改造后 |
|---|---|---|
| 兄弟分片裸引用 | 60 处（作用域分析实测） | **0 处** |
| 依赖可见性 | 看不出谁依赖谁 | `src/client/contracts.json` 固化 provider / consumer |
| 新增隐式依赖 | 只能靠人看 | `check:boundaries` 直接失败 |

校验命令：

```bash
npm run check:boundaries              # 校验
node scripts/check-client-boundaries.mjs --update   # 确认新增依赖后写回契约
```

检查器用 `espree + eslint-scope` 做**真实作用域分析**（不是正则），能区分
「同名局部变量」和「跨片引用」，也会校验 `Object.assign` 里登记的名字确实由本片定义。

## 5. P3：prompt 与构建产物单一真相

**prompt**：9 处各自拼 `join(HERE, '..', 'prompts', ...)` 收敛为一张版本表。

```js
import { PROMPT_VERSIONS, loadPrompt } from './prompts.js'
const system = loadPrompt(PROMPT_VERSIONS.deepRead)
```

- 升 prompt = 新增 `.md` + 改总表一行；
- 同一版本进程内只读一次磁盘；
- 文件缺失抛 `prompt_missing`，不会拿空 prompt 去调模型；
- `tests/prompts.test.mjs` 校验「总表 ↔ 文件」一一对应、各模块常量与总表一致。

**构建产物**：`lib/index.js` 与 `lib/client.js` 不再入库。

- `lib/` 下其余 40 个模块是手写源码，照常入库；只有两个拼接产物被 `.gitignore` 忽略；
- `src/` 是这两个产物的唯一可编辑来源；
- `package.json` 增加 `prepare`，`npm ci` / 从 git 安装都会自动构建；
- `npm pack` 仍然通过 `prepack` 构建，发布包内容不变；
- 删掉 `artifacts:check`（两个产物已不在版本库，`git diff` 无从比较）。

## 6. 加功能时的落点

| 你要加的东西 | 改哪里 |
|---|---|
| 一条 HTTP 路由 | 对应域的 `registerXxxRoutes` + `docs/28_API参考.md` |
| 一个领域能力（读/写库） | `lib/<domain>.js`，只依赖 `store.js` 与其它领域模块 |
| 换存储位置 / 多库 | `lib/store.js` 的 `createStore` / `useStore` |
| 一个 prompt | `prompts/<version>.md` + `lib/prompts.js` 总表 |
| 客户端一个新面板 | 新分片文件 + `Object.assign(SHARED, …)` + `contracts.json` 登记 |
| 客户端用别人的组件 | `SHARED.Xxx`，跑 `npm run check:boundaries` |
