## 1. 这一版做了什么

| # | 能力 | 说明 |
|---|---|---|
| 1 | 范围翻译 | 摘要+结论（默认）/ 本章 / 整篇 / 单块；整篇先确认 |
| 2 | 异步任务 | `POST /translate` 返回 202 + job；前端 2 秒轮询进度 |
| 3 | 三视图 | 原文 / 对照 / 译文；译文不覆盖原文，机翻标记常驻 |
| 4 | 术语表 | 内置 16 个领域词；可增删改；命中词强制译名；改动后译文懒失效 |
| 5 | 译后校验 | 块覆盖、非空、数字/单位/引用保留、术语命中、长度异常；失败块标红可重译 |
| 6 | 按块缓存 | `translations/<id>.zh.json`，按块存；模型/prompt/glossaryHash 变化失效 |
| 7 | 中文跳过 | 原文已是中文的块标记 `skipped`，不浪费模型调用 |
| 8 | 单块重译 | 每块有「译 / 重译」，只重跑该块 |

**没有**：译文导出 MD、双语 PDF、人工精校、图内文字翻译。

## 2. 接口

| 接口 | 行为 |
|---|---|
| `POST /api/litkb/translate` | `{id, scope, section?, blockIds?, force?}` → `202 {job}` |
| `GET /api/litkb/translate?id=` | `{doc, summary, job}`；前端轮询 |
| `GET/POST /api/litkb/glossary` | 术语表读写（最多 200 条） |

范围：`summary`（摘要+结论）/ `section` / `paper` / `block`。

存储：

```json
{
  "schema": 1,
  "paperId": "p-x",
  "target": "zh",
  "model": "deepseek-account/deepseek-flash",
  "prompt": "translate-zh.v1",
  "glossaryHash": "ab12cd34",
  "blocks": {
    "b-3f9a1c02": { "text": "……", "status": "ok", "page": 12, "issues": [] }
  }
}
```

状态：`ok` / `warn`（校验提示，不阻断）/ `failed`（无译文）/ `skipped`（原文中文）。

## 4. 你要做的初验（4 条）

> ⌘Q 退出 → 重新打开（版本 **0.4.0**）。

| # | 操作 | 通过标准 |
|---|---|---|
| 1 | 打开一篇英文论文 →「解析稿」→「翻译」 | 默认只译摘要+结论；出现进度，完成后切「对照」能看到中文 |
| 2 | 切「译文」 | 只看中文；未翻译的块显示「未翻译」，可单块「译」 |
| 3 | 打开「术语表」，改一个译名并保存，再「翻译」 | 新译文使用新译名；旧块会重译 |
| 4 | 选「整篇」→ 确认 | 长任务有进度；失败块标红，可单块重译 |

建议抽 20 段核对：术语一致、数字/引用没变、没有漏段。

## 7. 补丁（v0.4.1，术语表未生效）

**现象**：改一个译名、保存后再翻译，新译文仍用旧译名。

**根因**：术语表面板 16 行 + `max-height:280px`，保存按钮被挤到滚动区底部；实际没有点到「保存」，`glossary.json` 仍是默认词表，翻译自然用旧译名（已核对线上文件与 hash）。

**修复**：

- 保存按钮移到面板顶部，底部再加吸底保存条；
- 有未保存修改时显示「未保存」，关闭前二次确认；
- 保存后提示「已更新 N 条，重新点翻译才会生成新译文」；
- 用真实模型验证：把 `U-Net` 改成「U-Net 网络（测试）」→ 单块重译，译文确实使用新译名，校验无问题，随后已恢复原词表。
