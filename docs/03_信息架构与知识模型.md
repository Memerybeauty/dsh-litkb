## 2. 归类体系：一个大类 + 一组标签

### 2.1 轴定义

| 轴 | 取值 | 判定 | 用途 |
|---|---|---|---|
| **大类** | 学术期刊 / 学位论文 / 图书 / 会议 / 报纸 / 年鉴 / 专利 / 标准 / 成果 / 学术辑刊 / 文库 / 法律法规 | 规则：页面特征、venue、DOI、关键词；默认学术期刊 | 决定怎么读、怎么引 |
| **主题** | 扁平标签，自建 | 关键词命中（标题 ×3、正文每次 ×1） | 决定筛什么、图怎么连、写作时按什么找 |

### 2.2 标签体系（参考微信）

- **扁平**：不建树，标签名即标识，全局唯一；
- **多对多**：一篇多个标签，一个标签多篇；
- **可增删**：随时新建；删除需二次确认，并从所有论文上摘除；
- **关键词可选**：填了就自动打标，不填就纯手动；
- **无置信度**：命中即打，不命中不猜。

### 2.3 自动打标流程

```
规则判大类 ──▶ 关键词命中打标签（标题 ×3、正文 ×1，最多 5 个）
                     │
              有命中 ? ── 是 → 直接落库
                     └─ 否 → 进「未归类」→ 人加标签 / 新建标签
```

四条规则：

1. **大类用规则**，不用模型：venue / DOI / 页面特征足够，稳定优先；
2. **标签只从现有标签选**；不够用就"新建标签并打上"，一步完成；
3. **不设中间态**：没有置信度，也没有"疑似"，命中就是命中；
4. **删标签不删论文**：只摘标签，并在删除前告诉你影响多少篇。

### 2.4 初始标签（从现有文献反推，可随时增删）

| 标签 | 关键词示例 |
|---|---|
| 视盘视杯分割 | 视盘、视杯、杯盘比、glaucoma、optic disc、CDR |
| 极坐标与几何变换 | 极坐标、polar、几何变换 |
| 拓扑约束 | 拓扑、越界、包含关系 |
| 轻量化与部署 | 轻量、参数量、ONNX、推理速度 |
| 注意力机制 | 注意力、attention、SE、CBAM |
| 数据集与基准 | REFUGE、ORIGA、EyePACS、benchmark |
| 临床验证 | 临床、敏感度、医生、阅片 |
| 检索增强生成 | RAG、检索增强、知识库、问答系统 |
| 分割骨干 | U-Net、ResNet、Transformer、分割 |
| 医学影像大模型 | 大语言模型、LLM、多模态、VQA |

### 2.5 标签治理

| 频率 | 动作 |
|---|---|
| 每次导入 | 自动打标，未命中进「未归类」 |
| 每周 | 清一次「未归类」：补标签或新建标签 |
| 每月 | 合并同义标签、删掉长期 0 篇的标签 |

### 3.4 插件实际落盘结构（v0.4）

│   ├── edges.jsonl    # 全库边表（派生，可重建）
│   └── papers/<id>.json # 单篇抽取缓存（候选 + 合法边 + warnings）
├── exports/           # 综述草稿、refs.bib、解析稿.md
├── cache/pages/       # 页图 PNG（可删，重建）
├── drafts/            # 文稿 Markdown（P4.7）
├── deepread/<id>.json # 精读结构（P4.9）
├── chains/<id>.json   # 论证链（P4.10）
├── chains/.layout.json # 证据链知识库坐标（派生，可删）

├── tags.json

卡片 Markdown 仍是 Obsidian 可读的 frontmatter + 七段 + `^q-` 引文块；`blocks/`、`translations/`、
`concepts/`、`cache/` 是插件派生数据，删除后可重建（`concepts.json` 含人工合并结果，**不要删**；
`edges.jsonl` 与 `papers/*.json` 可删后重跑）。

## 4. 证据链：用 Obsidian 原生块引用

### 4.1 卡内引文块

```markdown
> 在 REFUGE 上，该方法取得 OD Dice 0.9645、OC Dice 0.8937，vCDR MAE 0.0347。 ^q-8f3a
> — Gao et al. 2024, Table 3, p.5
```

- `^q-8f3a` 是**引文块 ID**，由引文内容哈希生成（重跑不变）；
- 引文还要挂**版面块 ID**（`b-9c8d1a2b`）与 bbox：页面渲染后点引文即可用边框高亮原文那句话；
- 引文必须带 **页码**（图表号暂不自动识别，P3）；
- 引文前后各留一段上下文，防止断章取义。

### 4.2 引用与反查

| 动作 | 写法 | 效果 |
|---|---|---|
| 引一句 | `[[gao2024vcdr#^q-8f3a\|Gao 2024, p.5]]` | 点击跳原文 |
| 嵌一段 | `![[gao2024vcdr#^q-8f3a]]` | 直接显示原文 |
| 反查 | 打开卡片 → 反向链接面板 | 看到"这条证据被哪些笔记用过" |

### 4.3 硬约束

1. 稿子里没有块引用的句子 → 校验器标红，不许交付；
2. 引文块或版面块不存在（论文删了/重解析变了）→ 立刻提示，**不许静默失效**；版面块失效时退化为「按页定位」；
3. 区分 `author_claim`（作者原话）与 `my_note`（我的转述），两者不能混排。

### 4.4 可选：跨论文断言节点

```markdown
---
type: claim
id: C-0042
status: supported        # supported / contested / single-source
---
# 极坐标变换能显著提升视杯边界平滑度
- 支持：[[mnet2018#^q-1a2b]]、[[polarformer2023#^q-9c8d]]
- 反证：[[xxx2022#^q-77aa]]（单中心、样本 40）
```

当同一结论需要 3 篇以上支撑时，才值得单独立节点；否则留在卡片里即可。

### 4.5 论证链（P4.10 实现）

七段卡与精读回答「这篇说了什么」；论证链回答「我凭什么这么说」。

```json
{
  "id": "c-xxxxxxxx",
  "title": "极坐标变换改善视盘边界",
  "origin": "claim|evidence|question|block",
  "status": "draft|confirmed",
  "question": "可选：这条链回答的问题",
  "claim": {
    "text": "论点一句话",
    "paperId": "p-xxx",
    "sectionKey": "conclusion",
    "source": "deepread|manual"
  },
  "nodes": [
    {
      "id": "n-xxxxxxxx",
      "relation": "supports|contradicts|qualifies|derives|compares",
      "paperId": "p-xxx",
      "evidenceId": "q-xxxxxxxx",
      "page": 5,
      "block": "b-xxxxxxxx",
      "quote": "原文引文",
      "note": "可选：我的一句话说明"
    }
  ],
  "createdAt": "ISO",
  "updatedAt": "ISO"
}
```

铁律：

1. **claim 必须由用户确认**：AI 只提议，保存前可改；空 claim 不落库；
2. **节点只允许库内已有 q-id**：页码/块/引文从卡片证据复制，不接受模型给的页码；
3. **关系受控**：支持 / 反驳 / 限定 / 推导 / 对比五种，不允许自由文本；
4. **链落 `chains/<id>.json`**：一条链 = 一个可复用的论证单元，可重开、可删除；
5. **插入文稿**：弹窗内选目标文稿（或新建），生成 `[[p-xxx#^q-id|作者 年, p.N]]`；反链自动覆盖 `drafts/`；
6. **证据失效显式**：卡片重生成后节点若找不到 q-id，标 `stale`，不静默丢；
7. **原文段落建链**：解析稿里点任意正文段 → 若该段还没有 q-id，就按段落原文补一条证据（`block` 指向该段），再挂到 claim 上；页眉页脚不允许建链。

## 5. 知识图谱：三层，边必须有出处

| 层 | 节点 | 边 | 来源 |
|---|---|---|---|
| **L1 引文图** | 论文 | `cites` | OpenAlex / S2 的 references |
| **L2 概念图** | 论文、方法、数据集、指标 | `uses` / `improves_on` / `evaluates_on` / `reports` | 结构化抽取 + 概念归一 |
| **L3 证据图** | 断言、引文块、论文 | `supported_by` / `contradicts` | 写作与精读过程 |

### 5.1 边类型（受控）

| 边 | 语义 | 例子 |
|---|---|---|
| `uses` | 用了某方法/组件 | Gao2024 → Coordinate Attention |
| `improves_on` | 在谁的基础上改进 | CA-UNet → U-Net |
| `evaluates_on` | 在哪个数据集上评测 | Gao2024 → REFUGE |
| `reports` | 报告了某指标值 | Gao2024 → OC Dice 0.8937 |
| `contradicts` | 与某结论冲突 | A ↔ B |

> `reports` 带属性（指标、数值、数据集），这是"可比组"的来源。

### 5.5 概念归一与待归一（P3 实现）

```
模型抽候选 → normalizeTerm + 别名精确匹配
  ├─ 命中 → 直接用
  ├─ 与现有概念高度相似 → pending（待归一，不进图）
  └─ 其余 → 批量 LLM 判定
        ├─ same_as(已有) → 并入别名
        ├─ new → 新建 active
        └─ 不确定 / 模型不可用 → pending
```

- 归一化：NFKC → 小写 → 去空白/标点/连字符；`U-Net`、`UNet`、`u net` 同名；
- `pending` 的边先挂着，但不画；人工「合并 / 批准」后自动重建边表并进图；
- 合并只改词表与边表，不改单篇抽取缓存（保留可追溯性）。

**边的硬约束**：`source` 是论文或方法概念；`target` kind 必须匹配边类型；
`evidence` 必须存在于该论文卡片，`page/block/quote` 从证据复制；`reports.value` 必须是数字。

### 5.2 怎么用（四种渲染）

| 需求 | 用什么 | 说明 |
|---|---|---|
| 看形状 | Obsidian Graph View | 按 `path:` / `tag:` 过滤到单主题，别开全库 |
| 查表 | Dataview | "REFUGE 上 OC Dice > 0.87 的论文" |
| 编排演进图 | Canvas | 人工拖成答辩能用的图 |
| 算结构 | Python + networkx | 中心度、最短路径、可比组聚类 → 导出 Mermaid/Canvas |

### 5.3 为什么 v1 不上 Neo4j

- 你的规模是百篇级，Obsidian 链接 + Dataview 足够；
- 图数据库带来同步、部署、双写一致性三份成本；
- 真需要图算法时，从 Markdown 导出边表给 networkx 跑，十分钟的事。

**留一个后门**：所有边以 `edges.csv`（source, target, type, evidence, confidence）落盘，将来换任何图库都能一键导入。

### 5.4 防毛线球四条

1. 只画有 `evidence` 的边；
2. 概念节点必须来自受控词表，不接受自由文本；
3. 默认视图是"单主题子图"，不是全库；
4. 每个概念页写"入选标准"，说不清的不建页。

### 5.6 证据链知识库视图（P4.10+）

「图谱」页首屏不再画概念边，而是把 `chains/*.json` 聚合成一张可拖拽的论证图：

| 图元素 | 来源 | 说明 |
|---|---|---|
| `claim` 节点 | 每条链的 `claim` | 一条链一个；label 是论点，点开可回链 |
| `evidence` 节点 | 链的 `nodes[].evidenceId` | 同一 q-id 多链引用时只画一个（汇聚） |
| `paper` 节点 | 证据的 `paperId` | label 取索引标题；证据 → 论文画虚线 `excerpt` |
| 关系边 | `nodes[].relation` | supports / contradicts / qualifies / derives / compares |
| 失效 | 卡片里找不到 q-id | 节点/边保留并标黄虚线，不静默消失 |
| 未建链论文 | 索引里有、chains 里没有 | 仍画 paper 节点，暗色虚线，`chains=0`；统计「未建链 N」 |

节点数据同时带 `short`（≤10 字摘要）与 `full`（完整文本）：图上只画 `short`，右侧详情/悬停提示用 `full`；
论点蓝、证据绿、论文紫，关系边分色，失效黄虚线。

实现：Cytoscape.js（MIT，本地 `lib/vendor/cytoscape.min.js`，通过 `/api/litkb/vendor/cytoscape.js` 懒加载）；
布局坐标存 `chains/.layout.json`（只存 `id → {x,y}`，可删可重建）；节点拖动 600ms 后自动保存。

边界：**图是只读视图**。建链/改链仍在弹窗；图上只做导航（打开链、回原文、打开论文）与布局。

## 6. 精读页：一篇文章的七段式

卡片正文固定七段（顺序固定，便于横向对比）：

| # | 段落 | 必须回答 | 反例 |
|---|---|---|---|
| 1 | 一句话 | 它解决了什么、怎么解决 | "提出了一种新方法" |
| 2 | 问题与动机 | 现有方法差在哪 | 复述摘要 |
| 3 | 方法 | 模块级拆解 + 关键图/公式 | 只写"用了 U-Net" |
| 4 | 数据与实验 | 数据集、划分、对比对象 | 漏掉评测协议 |
| 5 | 结果 | 具体数字（表） | "效果显著提升" |
| 6 | 局限 | 作者自述 vs 我的判断（分开写） | 把作者局限当结论 |
| 7 | 与我的课题 | 可引在哪 / 能否当 baseline / 要不要复现 | 空着不写 |

交互：

- 右栏原文页图连续滚动，点引文页码直接跳并高亮；
- 逐段追问：选中解析稿块或卡片正文后问"它和 baseline 的差别在哪"，回答必须带本文页码；
- 追问材料 = 选中段 + 同页上下文 + 七段卡 + 证据；问题点名另一篇时补它的卡片（最多 2 篇）；追问在右栏内联；
- 页码白名单：回答里的 `[p.N]` 必须在材料页码内；越界标红、不计引用；没依据写"原文没有足够依据"；
- 术语表在「标签与术语」管理页维护，不覆盖原文；
- 批注回写：你的批注追加到 `## 我的批注`，带日期，不覆盖原文。

阅读状态机：

```
待读 ──略读──▶ 略读 ──精读──▶ 精读 ──引用──▶ 已引用
  └──────────弃读──────────▶ 弃读（记录原因）
```

## 8. 三条不可妥协

1. **受控词表**——类目与概念不自由生长，扩张必须走"建议 → 人批"；
2. **块级证据**——每条结论落到具体块，块没了就报错；
3. **失败显式**——识别不了、解析不了、归一不了，全部进队列，不许猜；
4. **页码可核**——追问回答的每个 `[p.N]` 必须能落回材料；落不回就标红，不装作有出处。
