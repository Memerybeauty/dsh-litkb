## 1. 这一阶段做了什么

| # | 能力 | 说明 |
|---|---|---|
| 1 | 分页分行文本 | 用文字块坐标还原行序，缓存 `text/<id>.pages.json`；旧论文首次生成时自动重建 |
| 2 | 章节切分 | 整行标题、行首内联标题（「摘要针对…」）、编号标题（`2 系统总体设计`）三类；排除目录、页眉、图题 |
| 3 | 七段生成 | 摘要/引言/方法/实验/结果/结论按预算裁剪（≤48k 字符），一次调用输出七段 JSON |
| 4 | 块级证据 | 模型给的引文逐条回贴原文，页码以定位结果为准；定位失败丢弃并记警告 |
| 5 | 块 ID | `^q-` + 归一化引文的 8 位哈希；同一引文重跑不变 |
| 6 | 卡片页 | 详情抽屉新增「七段卡」页签：生成、进度轮询、失败原因、重新生成 |
| 7 | 原文跳转 | 每条引文带 `p.N`，点开浏览器 PDF 到对应页 |
| 8 | 断链提示 | PDF 被删后打开卡片：明确提示断链，不崩溃 |

**没有**：逐段编辑、批注、内嵌 PDF 高亮、扫描件 OCR。

对应开发计划：本版覆盖 **P2-1 七段生成、P2-2 证据抽取、P2-3 卡片页** 的主链路；
P2-4（内嵌阅读器 + 高亮）与 P2-5（状态机 + 批注）留到 P2.2 / P2.3。

## 2. 证据口径（三条硬规则）

1. **只认原文**：模型给的 `quote` 去掉空白与标点后必须能在某一页原文里找到；
2. **页码以定位为准**：模型给的页码只作提示，最终页码来自原文命中位置；
3. **找不到就丢**：整段都对不上时丢弃该引文，并在卡片里写「生成警告」，绝不改写成通顺句。

块 ID 由引文内容决定：同一句话无论是哪次生成，ID 都不变（`^q-1a2b3c4d`）。

## 4. 你要做的初验（4 条）

> 先 ⌘Q 退出 → 重新打开（插件是 link 安装，无需重装；若侧边栏没有，再跑一次 §5 的命令）。

| # | 操作 | 通过标准 |
|---|---|---|
| 1 | 打开一篇 → 「七段卡」→「生成七段卡」 | 1–3 分钟内出现七段，状态显示「七段完整」或「部分待补」 |
| 2 | 读七段 | 每段 2–4 句、有具体信息；没有内容的段会明确写「需人工补充」 |
| 3 | 点段落下方的 `p.N` | 新标签打开 PDF 并定位到该页 |
| 4 | 「重新生成」 | 二次确认后重新生成；旧版在 `cards/.versions/` |

可选：删掉某篇 PDF 再打开卡片，应显示「原文 PDF 已缺失（断链）」。

## 6. 七段结构

| # | 键 | 段落 |
|---|---|---|
| 1 | `oneLine` | 一句话：解决了什么、怎么解决 |
| 2 | `problem` | 问题与动机 |
| 3 | `method` | 方法（模块级拆解） |
| 4 | `data` | 数据与实验 |
| 5 | `results` | 结果（具体数字） |
| 6 | `limits` | 局限（作者自述 / 我的判断） |
| 7 | `relevance` | 与我的课题（可引在哪、能否当 baseline） |

落盘：`cards/<id>.card.json`（机读） + `cards/<id>.md`（Obsidian 可开，含 frontmatter 与块引用）。

## 8. 补丁（2026-11-05，v0.3.2）

**问题**：生成七段卡时报「模型输出被截断（max-tokens），请重试」。

**原因**：DeepSeek 默认 reasoning effort 为 high，思考 token 与正文共用 `max_tokens` 预算；4096 不足以容纳「思考 + 七段 JSON」。

**修复**：

1. 生成时显式 `reasoningEffort: "off"`，结构化抽取不需要思考链；
2. 输出上限提到 **8192** token；
3. 提示词升级 [seven-sections.v2.md](../prompts/seven-sections.v2.md)：每段 ≤120 字、每段最多 2 条引文、引文 ≤60 字；
4. 仍截断时自动用「紧凑输出」提示重试一次，而不是直接报错；
5. 增加参数与截断重试的单测。
