## 1. 总览

| 阶段 | 工期 | 目标 | 闸门 |
|---|---|---|---|
| **P0 脚手架** | 2 天 | 装得上、开得开、卸得掉 | G1 |
| **P1 收文与归类** | 4 天 | 拖进去能归位 | G2 |
| **P2 卡片与证据** | 5 天 | 打开能读懂、能跳原文 | G3 |
| **P3 图谱与精读** | 4 天 | 连得起来、问得下去 | G4 |
| **P4 界面融合与打磨** | 9–11 天 | 原生工作区 + 能交付给别人用 | G5 |

### 1.1 四个排期原则

1. **先证明装得上**——插件形态最大的风险是"装不进去"，P0 只干这一件事；
2. **先数据后界面**——解析与归类不通，界面做得再漂亮也是空壳；
3. **先证据后图谱**——没有证据的图是装饰，顺序不能反；
4. **每阶段可演示**——每个闸门都能当场演示，不演示不进入下一阶段。

---

## 2. 关键路径

```
P0 装得上
   └─▶ P1 解析 ─▶ P1 归类 ─▶ P2 七段卡 ─▶ P2 证据 ─▶ P3 图谱 ─▶ P4 导出
                              └─▶ P2 卡片页 ─▶ P3 精读
```

**卡点**：P1-3（解析质量）决定后面所有环节的天花板；若 pdfjs 对中文样本效果差，必须在 G2 前决定是否加 OCR 兜底，不能拖到 P2。

## 6. 风险与缓冲

| 风险 | 触发信号 | 处理 | 预留 |
|---|---|---|---|
| 插件 API 装不上 | P0 卡住 | 参考 `dsh-worktable` 源码，必要时降级为"网页版 UI + 本地服务" | 2 天 |
| pdfjs 中文解析差 | G2 前 3 篇质量分 < 0.5 | 加 OCR 可选通道；卡片标注"依据不足" | 1 天 |
| 归类不准 | G2 准确率 < 85% | 先收紧词表 + 增加 few-shot；不硬上 | 1 天 |
| 与 worktable 布局冲突 | P0 演示异常 | 互斥开关 / 页签嵌入 | 0.5 天 |
| 模型成本超预期 | 单篇 > ¥1 | 降级模型、减少重排 | — |

**总缓冲 3 天**，只用于上述风险，不用于加需求。
