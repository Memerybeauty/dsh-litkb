## 1. 现状与问题

### 1.1 匹配

当前 `matchFacet` 的规则全部硬编码：

```js
const MAX_HITS = 8
const MAX_PAPERS = 6
const PER_PAPER = 2
score >= Math.max(1.5, top * 0.4)
关键词非空 → 必须命中（硬过滤）
标签 → 只加分（+1.5/个，上限 3）
```

问题：

1. 用户无法调阈值、每篇上限、关键词是否强制；
2. 没有年份/标签的硬筛选；
3. 同义改写召不回（BM25 只认字面）；
4. 命中后只显示分数，不解释"为什么是这篇"；
5. 缺口原因只有一句笼统提示。

### 1.2 结论与链

- `summary` 只有 `text / updatedAt / model`，没有记录"基于哪些链"；
- 链确认/拒绝/修改后，结论不会提示过期；
- 审核只能一条一条点，没有批量；链合并没有 UI（API 有 merge）。

## 2. 匹配可调

### 2.1 数据模型

`themes/<id>.json` 增加 `match`（缺省时用默认值，旧研究无需迁移）：

```json
"match": {
  "minScore": 1.5,
  "relative": 0.4,
  "perPaper": 2,
  "maxHits": 8,
  "maxPapers": 6,
  "keywordMode": "require",   // require | off
  "tagMode": "boost",          // boost | require
  "yearFrom": 0,
  "yearTo": 0,
  "expand": true               // 同义/别名扩展
}
```

默认值 = 当前行为，只是 `expand` 默认开（只加词、不改硬规则；可关）。

约束：`minScore 0.5–10`、`relative 0.1–0.9`、`perPaper 1–3`、`maxHits 4–12`、`maxPapers 3–10`、年份合法区间。

### 2.2 匹配算法变化

```text
query = facet.title + description + keywords
queryTokens = tokenize(query)
if (match.expand) queryTokens += 别名扩展（见 2.3）

候选 = evidence docs + card section docs + deepread claim docs
for doc:
  if (tagMode === 'require' && 论文标签 ∩ theme.tags == ∅) continue
  if (year 不在 [yearFrom, yearTo]) continue
  if (keywordMode === 'require' && keywords 非空 && 未命中) continue
  bm25 = score(doc)
  tag = 命中标签数 × 1.5（上限 3）
  concept = 命中概念数 × 0.5（上限 2）
  score = bm25 + tag + concept

按 score 排序 → 每篇 ≤ perPaper、论文 ≤ maxPapers、总 ≤ maxHits
保留 score ≥ max(minScore, top × relative)
```

### 2.3 同义/别名扩展（不做向量）

- 来源：`concepts/concepts.json` 的 `name + aliases`、标签的 `keywords`；
- 用法：query 里出现某概念名/别名时，把它其余别名追加进 query tokens（每个概念最多 3 个，总数 ≤12）；
- 只加召回，不加权重；命中时在明细里标 `expandedBy`；
- 不做 embedding、不引模型。

### 2.4 可解释输出

`matchFacet` 每条命中返回：

```json
{
  "paperId": "p-...", "evidenceId": "q-...", "page": 3, "quote": "...",
  "score": 5.2,
  "parts": { "bm25": 3.2, "tag": 1.5, "concept": 0.5 },
  "matched": ["polar", "边界"],
  "expandedBy": ["polar transform → 极坐标变换"],
  "keywordHit": true
}
```

缺口返回结构化原因：

```json
{ "gap": true, "reasonCode": "keywords_miss | tag_filter_empty | year_filter_empty | below_threshold | no_corpus", "reason": "..." }
```

### 2.5 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/themes/save` | 增加可选 `match`（不传则保留原值） |
| POST | `/themes/match` | 返回 `results[].hits[].parts/matched/expandedBy` 与 `reasonCode`；可带 `override.match` 做临时试算 |
| POST | `/themes/explore` | 使用 theme.match 跑；响应回传实际使用的配置 |

不新增路由，`/themes/read` 返回 `theme.match`。

### 2.6 界面

**匹配设置弹窗**（参考论文头部「匹配设置」）：

```text
匹配设置
关键词   (•) 必须命中   ( ) 不强制
标签     (•) 只加分     ( ) 必须命中
年份     [2020] – [2026]
阈值     [====|-----] 1.5      相对阈值 [==|------] 0.4
每篇上限 [2 ▾]   结果上限 [8 ▾]   论文上限 [6 ▾]
[x] 启用同义/别名扩展
[恢复默认]                    [取消] [保存]
```

保存后提示「已保存；重新探索后生效」，并自动跑一次 explore（可配置为仅保存）。

**匹配明细抽屉**（「匹配明细」）：

- 按细分分组；
- 每条命中：论文、p.N、引文、`5.2 = 3.2 BM25 + 1.5 标签 + 0.5 概念`、命中词、扩展词；
- 缺口：原因代码 + 建议（如「关键词未命中，删掉 1 个关键词或改用不强制」）；
- 可点「只跑这条」。

## 3. 结论与链同步

### 3.1 数据模型

`theme.summary` 增加 `basis`：

```json
"summary": {
  "text": "...",
  "updatedAt": "...",
  "model": null,
  "basis": {
    "chainIds": ["c-1", "c-4"],
    "fingerprint": "sha1(chain.id + updatedAt + claim + evidenceIds, 排序后)"
  }
}
```

指纹只算**已确认链**；draft 不参与。

### 3.2 过期判定

`/themes/read` 返回：

```json
"summaryState": {
  "stale": true,
  "reason": "已确认链有变化（新增 1 条 / 修改 2 条）",
  "current": { "chainIds": [...], "fingerprint": "..." },
  "saved": { "chainIds": [...], "fingerprint": "..." }
}
```

规则：

- 手写保存 `text` 时，把 `basis` 写为当前指纹（视为按当前链写的）；
- 生成结论时写当前指纹；
- 无 `basis` 的旧结论：`stale=false`，但提示「旧版结论，未记录依据」。

### 3.3 界面

- 研究结论页顶部：`结论已过期（新增 1 条链）` + [重新生成]；
- 证据链视图的「研究结论」大卡显示黄点；
- 生成时若 stale，按钮文案「重新生成」。

## 4. 链批量审核与合并

### 4.1 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/chains/review/batch` | `{ ids, action: 'accept'|'reject' }`，逐条返回结果，单条失败不中断 |
| 复用 | `/chains/review` | `action:'merge', id, targetId`（已有） |

批量结果：

```json
{ "ok": true, "action": "accept", "succeeded": 3, "failed": 0, "results": [{ "id": "c-1", "ok": true }] }
```

### 4.2 界面

证据链视图列表：

- 每条链前加 checkbox；顶部「全选草稿 / 清空」；
- 选中后出现操作条：`已选 3 条  [批量确认] [批量拒绝] [合并…]`；
- 「合并」要求恰好选 2 条：弹窗选择保留哪条（目标），另一条并入后删除；
- 操作完成刷新列表与统计；结论 stale 自动出现。

## 5. 兼容与迁移

- 旧 `themes/*.json` 无 `match` → 读时补默认值，不写回；
- 旧 `summary` 无 `basis` → `stale=false`，标「旧版结论」；
- 旧链无 `updatedAt` → 指纹用 `createdAt` 兜底；
- 不改索引、不加快照。

## 8. 风险

| 风险 | 对策 |
|---|---|
| 改默认值影响旧研究 | 默认完全等于旧行为，只有显式改配置才变 |
| 扩展导致误召回 | 只加词、不加权；明细标 `expandedBy`；可关 |
| 阈值调低后链暴增 | `maxHits/maxPapers/perPaper` 同时可调；链仍是 draft + 审核 |
| 结论过期误报 | 指纹只算已确认链；手写保存写当前指纹 |
| 批量部分失败 | 逐条结果返回，UI 显示成功/失败数 |
| 合并误删 | 弹窗明确"保留哪条、删除哪条"；合并后仍可撤销？不提供，靠确认 |
