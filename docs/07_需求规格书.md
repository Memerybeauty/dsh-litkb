## 1. 引言

### 1.1 目的

定义文献知识库插件的功能需求、接口、数据与验收标准，作为开发、测试与验收的唯一依据。

### 1.2 范围

DeepSeek Harness 插件 `dsh-litkb`：收文、三轴归类、解析、七段卡、证据链、图谱、检索、精读、导出、Agent 工具。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 库（Library） | 用户选定的本地文件夹，含 papers/cards/concepts/exports/index |
| 卡片（Card） | 一篇论文的 Markdown 笔记，七段式 + 证据块 |
| 证据块（Evidence） | 带 `^q-xxxx` 标识的引文，含页码与上下文 |
| 三轴 | 体裁（type）、主题（topics）、角色（roles） |
| 概念（Concept） | 方法 / 数据集 / 指标，受控词表节点 |
| 边（Edge） | 概念或论文之间的关系，必须挂 evidence |
| 闸门（Gate） | 阶段验收点 |

## 2. 总体描述

### 2.1 产品视角

插件运行于 DeepSeek Harness：

```
DSH 宿主
├── 服务端插件（Node）  ── 路由 /api/litkb/* · 管线 · 工具
├── 客户端插件（React） ── 侧边栏入口 · 工作区 · 设置卡片
└── 本地库文件夹        ── papers / cards / concepts / index
```

### 2.2 用户特征

单用户、本地、中文优先；熟悉 Obsidian 与命令行；不接受"看起来对但其实是编的"。

### 2.3 约束

| 编号 | 约束 |
|---|---|
| C-01 | 纯 Node/TypeScript 实现，不依赖 Python 或本地模型服务 |
| C-02 | 必须通过 `dsh plugin add` 安装，安装后无需额外配置即可启动 |
| C-03 | 库必须是纯 Markdown + PDF，可用 Obsidian 直接打开 |
| C-04 | 不联网也能浏览已入库内容（仅生成类功能需要模型） |
| C-05 | 模型调用优先走宿主，其次用设置中的 API key |

### 2.4 假设与依赖

- 宿主提供：webserver 路由、客户端 slot、模型服务、会话服务；
- 用户有可写的本地目录；
- PDF 为文本型或可 OCR，扫描件允许降级。

## 3. 功能需求

| ID | 需求 | 规则与边界 | 优先级 | 验收 |

## 5. 数据需求

### 5.1 实体

| 实体 | 关键字段 | 约束 |
|---|---|---|
| Paper | paper_id, citekey, doi, title, authors, year, venue, sha256, pdf_path, type, topics[], edited, status | citekey 唯一；sha256 唯一 |
| Card | paper_id, sections{}, evidence_count, schema_version | 与 Paper 1:1 |
| Evidence | evidence_id, paper_id, page, quote, context_before, context_after, kind | evidence_id 唯一；quote 非空 |
| Concept | concept_id, kind(method/dataset/metric), name, aliases[], definition, status(active/pending), source | id 稳定；name 在同 kind 下唯一（归一化后）；pending 不进图 |
| Tag | name, keywords[], count, created, updated | name 唯一；删除即从论文摘除 |
| Edge | id, source, target, type, paper, evidence_id, page, block, quote, metric, value, dataset, unit, confidence, at | evidence_id 必填且属于该论文；reports 的 value 为数字；source 为论文或方法概念 |
| ConceptAnalysis | paper_id, model, prompt, concepts[], edges[], warnings[], at | 单篇抽取缓存；可重建边表 |
| Claim | claim_id, text, status, evidence_ids[] | 至少 1 条证据（除 status=unsupported） |
| Job | job_id, paper_id, stage, status, attempts, error_code | — |
| Setting | key, value | — |

### 5.2 数据完整性

- 卡片必须能追溯到 Paper；
- 证据必须能定位到 PDF 页码；
- 边必须挂 evidence；
- 删除 Paper 时级联删除 Card/Evidence，并在 Edge 上标记悬空；
- Edge 的 paper 必须存在于 index；target 必须是 active 概念；
- Concept 合并后，所有引用旧 ID 的边重指到新 ID，不留下悬空边。

### 5.3 迁移与备份

- `schema_version` 写在 `index.jsonl` 首行；
- 升级时先备份 `index.jsonl.bak`；
- 卡片与 PDF 不迁移（原地兼容）。
