## 1. 安装与升级

1. 把 `dsh-litkb-0.3.2.tgz` 安装到 DSH profile（当前开发环境为 link 安装）；
2. **完全退出 DSH 再启动**（服务端路由/工具只在进程启动时注册）；
3. 启动后 `Cmd+Shift+R` 强制刷新前端；
4. 验证：

```bash
curl http://127.0.0.1:<端口>/api/litkb/health
# version: "0.3.2"
```

> 只刷新页面不会加载新的服务端路由；`/deepread/compare` 404 就是旧进程导致的。

## 2. 验收主路径

### 2.1 收文

- 论文库 → 拖入 PDF / 「＋ 导入 PDF」；
- 论文库 → 「链接 / DOI」→ 贴 DOI、arXiv ID 或 PDF 链接；
- 应看到：分类、标签、卡片骨架；重复文件提示「已在库中」。

### 2.2 精读 / 七段卡

- 打开论文 → 七段卡生成/编辑；
- 详情 → **精读**（不再叫「11板块」）→ 生成/查看 11 板块；
- 精读左侧导航可 **隐藏导航 / 显示导航**。

### 2.3 自动建链 / 审核

- 论文行右侧 → **自动建链**（单篇）；
- 图谱页 → 自动建链/审核（整库 / 跨论文对比/矛盾）；
- 无精读时自动用七段卡兜底，草稿带 warning；
- 审核队列：确认 / 拒绝 / 查看；确认后才进入图谱与检索。

### 2.4 横向精读

- 论文库 → **横向精读** → 选 2–4 篇 → 加载对比；
- 文本/数字差异标记、「只看差异」、折叠；
- 「对比链」生成 evidence-mode 草稿；
- 「存为文稿」切到写作页。

### 2.5 检索 / 问答

- 论文库 → **检索**：论文/标签/年份过滤；
- 链答案 / 只看证据；
- 引用 p.N 回原文；复制答案 / 存为文稿；
- 最近检索 ≥10 条（实际落盘 50 条）。

### 2.6 Agent 工具

12 个：

`lit_search / lit_answer / lit_chain_get / lit_chain_propose / lit_chain_save / lit_card / lit_cite / lit_graph / lit_blocks / lit_theme_list / lit_theme_match / lit_theme_chain`

- 读工具只读；
- `lit_chain_save`、`lit_theme_chain` 必须 `confirm:true`；
- 检索类工具自动写最近检索历史。

### 2.7 研究工作台

- 单页结构：工作台是首页；论文库/写作从首页入口卡进入，页头可返回；
- 个人工作台：顶部三张数字卡 + 研究卡片；点研究进入三个大视图卡；
- 「＋ 新建研究」：标题 + 细分描述（可点「AI 帮我拆」）；
- 点「开始探索」：一次完成匹配论文 + 建立证据链（后台任务，进度可见）；
- **参考论文**：只列本研究的论文（可搜）；点开就是论文阅读页，默认落在精读页签；头部可「匹配设置 / 匹配明细」；
- **证据链**：左侧链列表（按细分分组、可筛选、可多选），右侧链详情；支持批量确认/拒绝与两链合并；
- **研究结论**：左侧结论（生成/编辑），右侧是支撑它的已确认链；链变化会提示结论过期；
- 切到论文库或写作再回来，工作台保持原来的研究和视图；
- 论文库：保留原布局（论文 / 横向精读 / 图谱 / 检索）；
- 写作：独立模块，按研究筛选。

## 6. 维护

```bash
npm test
npm run check
npm pack
```

新增客户端组件时注意：

- 不要复用旧组件的 CSS 类名（v0.28.3 的横向表裁切就是 `litkb-compareTable` 冲突）；
- 主题色只用 `--litkb-*`，不要写死深色；
- 新增服务端路由后必须重启 DSH；
- 新增工具后更新 `docs/19`、`docs/26` 与测试计数。


## 7. 代码质量现状（v0.2.14）

### 已做

- 客户端拆为 `src/client/00–70` 九个片段，服务端拆为 `src/server/00–80` 九个片段；
- `npm run build` 用无依赖脚本拼接生成 `lib/client.js` / `lib/index.js`；
- 服务端按职责拆出：`search.js`、`answer.js`、`agent-tools.js`、`chain-cross.js`、`search-history.js`、`link-import.js`；
- PDF 导入抽出 `importPdfBuffer`，本地/链接导入共用一套去重、解析、分类、落卡流程；
- 概念图谱用 Cytoscape；证据链/概念图共用主题与 tooltip；
- BM25 30 篇/300 证据检索 18–21ms；
- 修过结构性问题：UI 令牌自引用、`litkb-compareTable` 类名冲突、横向精读 404 兼容、自动建链无精读兜底；
- 工具注册用 `ctx.effect` 返回 disposer，避免 HMR 重复注册；
- 128 项测试 + 75 路由冒烟；
- `npm run lint`（ESLint 9 flat config，0 error / 0 warning）；
- `npm run format:check`（Prettier 3，no semi / 单引号 / 120 列）；
- `npm run coverage`（c8：语句 77.5% / 分支 57.8% / 函数 74.0%，阈值 lines 70 / functions 65）；
- GitHub Actions CI：check → lint → test → coverage。

### 没做（有意推迟）

| 项 | 现状 | 原因 |
|---|---|---|
| 类型检查 | 已有 ESLint + Prettier；没有 TS/checkJs | 片段式共享作用域不适合直接加类型；等 ESM 拆分后再上 |
| 真正 ESM 模块化 | `src/client` 片段共享 factory 作用域，不是独立 import/export | 为了保持 DSH ModuleLoader 单文件加载、不引入 bundler；后续可评估 esbuild |
| 搜索索引缓存 | 每次查询重建 BM25 corpus | 当前 30 篇 18–21ms，够用；论文上千再上缓存 |
| 清理旧 Canvas 代码 | `computeForceLayout` / `drawGraph` 保留给测试/回退 | 直接删会改测试与回退路径，暂不冒险 |
| 概念图谱 UI | 暂时隐藏，代码保留 | 产品决定，不是代码问题 |
| 覆盖率门槛 | 有 c8 与 70/65 阈值；分支覆盖仍偏低（57.8%） | 先防回退，后续补路由/异常分支 |

结论：**已补齐 ESLint + Prettier + CI + 覆盖率**，但仍是“拼接式单文件”架构，没有类型检查与 ESM。后续优先搜索索引缓存与 ESM 评估。
