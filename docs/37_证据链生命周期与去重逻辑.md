# 证据链生命周期与去重逻辑（v0.6）

| 项 | 内容 |
|---|---|
| 状态 | 已实施（v0.6.0） |
| 目标 | 同一细分只有一条“主确认链”；补充草稿确认时并回主链；历史重复可一键合并 |
| 涉及 | `lib/themes.js`、`/chains/review`、`/chains/dedupe`、研究工作台证据链视图 |

---

## 1. 链的两种状态

| 状态 | 含义 | 是否参与结论/检索/图谱 |
|---|---|---|
| `draft` | 自动生成或手工创建的候选，待人工审核 | 否 |
| `confirmed` | 人工确认，作为该细分的主链 | 是 |

主题链额外带：

```json
"provenance": {
  "themeId": "t-...",
  "facetKey": "f1",
  "previousChainId": "c-..."   // 仅“补充草稿”有
}
```

---

## 2. 生成规则（explore）

对每个细分：

1. 已有 **confirmed**：生成一条**补充草稿**，`provenance.previousChainId` 指向主链，并提示“不会覆盖原链”；
2. 已有 **draft**：原地更新这条草稿（`existingChainId`），不新增；
3. 都没有：新建一条普通草稿。

> 生成阶段永远不覆盖 confirmed，也不会自动把草稿转正。

---

## 3. 审核规则（accept）

### 3.1 普通草稿，且该细分没有 confirmed

直接转 confirmed。

### 3.2 补充草稿，或该细分已有 confirmed

不再产生第二条 confirmed，而是：

```text
主链 nodes ∪ 草稿 nodes（按 evidenceId 去重，最多 12 条）
→ 写回主链，status = confirmed
→ 删除草稿
→ 返回 { merged: true }
```

主链的 claim / title / question 保持不变，只补充证据。

### 3.3 手动合并（merge）

选两条链，指定保留目标；节点并集后删除源链。用于跨细分或人工整理。

### 3.4 历史重复（dedupe）

v0.6.0 之前可能已经存在同一细分多条 confirmed。新增：

```http
POST /api/litkb/chains/dedupe
{ "themeId": "t-..." }
```

规则：

- 按 `facetKey` 分组，只处理 confirmed；
- 每组保留 `createdAt` 最早的一条为主链；
- 节点并集、去重、最多 12 条；
- 删除其余链；
- 返回 `{ groups, removed }`。

界面在证据链视图检测到重复组时显示：

```text
有 N 组细分存在多条已确认链    [合并重复]
```

---

## 4. 为什么这样设计

- **一个细分一条主链**：结论、提纲、图谱都按 facet 取链，多条 confirmed 会导致重复引用与统计虚高；
- **补充草稿不另立门户**：新证据应该增强主链，而不是制造第二条“已确认”；
- **生成与审核分离**：explore 只产草稿，人工确认才进入结论/检索；
- **历史数据不静默删除**：重复合并必须由用户点「合并重复」，避免误删。

---

## 5. 边界与后续

- 没有 `facetKey` 的链（手工链）不参与按细分去重；
- 节点上限 12，超出部分丢弃；
- 合并后主链的 claim 不自动改写；如需改论点，走链编辑；
- 后续可加“链版本/撤销”，当前只保留 `review.from` 记录合并来源。
