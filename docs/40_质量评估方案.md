# 30 篇质量评估方案（v0.9.2）

| 项 | 内容 |
|---|---|
| 状态 | 脚手架已就绪，待 30 篇样本 + 人工评分 |
| 命令 | `npm run eval` → `eval/quality-<时间>/` |
| 产物 | `report.md`（逐链清单）、`scores.csv`（人工评分表）、`summary.json`（自动指标） |

## 1. 样本

- 30 篇：10 篇核心主题 + 20 篇随机/边缘；
- 每篇至少一张七段卡；覆盖期刊、会议、学位论文各类型；
- 建 2–3 个真实研究，每个 4–6 个细分。

## 2. 指标

| 层 | 指标 | 计算 |
|---|---|---|
| 匹配 | 细分覆盖率 | 有 confirmed 链的细分 / 总细分 |
| 匹配 | 命中切题率 | 人工对每条命中 1–5 分，≥3 视为切题 |
| 链 | 证据可定位率 | 节点 q-id 能在对应论文卡片中找到（脚本自动） |
| 链 | 链 precision | 人工：节点是否支撑论点，1–5 分，≥3 计入 |
| 链 | 重复组 | 同一细分多条 confirmed 的组数（脚本自动） |
| 结论 | groundedness | 结论每条能否回到链，1–5 分 |
| 写作 | 引用解析率 | 文稿引用能解析到 q-id 的比例 |

## 3. 评分表

`scores.csv` 列：

```text
theme_id, theme_title, facet_key, facet_title, chain_id, status, claim,
nodes, locatable, human_relevance, human_support, human_grounded, notes
```

人工填：

- `human_relevance`：这条链是否切题（1–5）；
- `human_support`：节点是否支撑论点（1–5）；
- `human_grounded`：结论是否由链支撑（1–5，按细分填一次即可）。

## 4. 当前干跑（4 篇）

最近一次 `npm run eval` 的结果：

```text
论文 4 · 已确认链 20 · 证据可定位 100% · 细分覆盖 72% · 重复组 5
```

说明：

- 可定位率 100% 是脚本按节点自己的论文卡片核对后的结果；
- 重复组 5 是历史数据未执行「合并重复」，评估前应先在工作台点一次合并；
- 细分覆盖 72% 表示 18 个细分里有 13 个已有 confirmed 链。

## 5. 流程

1. 导入 30 篇，生成七段卡；
2. 建 2–3 个研究，跑探索、审核链、生成结论；
3. `npm run eval` 导出评估表；
4. 人工填 `scores.csv`；
5. 汇总：按 `theme_title` / `facet_title` 求均值，列出 <3 分的链；
6. 问题清单按频率修，不按单条特例改规则。

## 6. 通过标准（建议）

- 证据可定位率 ≥ 98%；
- 链 precision 均值 ≥ 3.5；
- 细分覆盖率 ≥ 80%；
- 结论 groundedness 均值 ≥ 3.5；
- 引用解析率 100%。

未达标项进入下一轮优化，不直接加新功能。
