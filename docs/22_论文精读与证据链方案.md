## 0. 为什么现在做

现在能读、能写，但缺一个关键层：

- **七段卡**是「这篇论文讲了什么」的摘要；
- **写作引用**是「这句话来自哪一页」的引用；
- 中间缺的是：**这篇论文的哪个论断，被哪几条证据支持/反驳，能不能直接拿来论证**。

所以下一阶段不是继续加写作按钮，而是补：

> **论文精读 → 论断（claim）→ 证据（evidence）→ 证据链（chain）→ 写进文稿**

这条链打通后，写作时插入的不再是「一条引文」，而是「一个有论点的论证单元」。

## 1. 现有资产与缺口

| 已有 | 能做什么 | 缺什么 |
|---|---|---|
| `blocks/<id>.json` | 页码、bbox、章节、可定位 | 没有「论断」层 |
| 七段卡 + `q-` 证据 | 摘要 + 引文 | 摘要级，不是 claim 级 |
| `concepts/edges.jsonl` | 方法/数据集/指标关系 | 不是论证关系 |
| 写作 `drafts/` | 引用 `[[paper#^q-id]]` | 只能逐条引用，不能插「论证单元」 |
| 反链 | 证据被谁引用 | 没有「证据链」对象 |

**缺口结论**：需要新增 `deepread/` 与 `chains/` 两层，不动现有 blocks/cards。

## 2. 论文精读：产出什么

精读不是把原文抄一遍，而是用**自己的话**写成 11 个固定板块的结构化 Markdown 说明。

### 11 个板块

| # | 板块 | 要写什么 |
|---|---|---|
| 1 | 文献基本资料 | 标题、作者、期刊/会议、年份、DOI、类型 |
| 2 | 研究内容 | 研究问题、缺口、目标、假设 |
| 3 | 方法 | 设计、模型/算法/材料、流程、对照 |
| 4 | 样本量 | 样本数、数据集、训练/验证/测试划分 |
| 5 | 研究时间 | 数据收集、实验、随访时间 |
| 6 | 图表解析 | 逐图/表说明展示什么、关键趋势/数值 |
| 7 | 结论 | 作者结论与适用范围 |
| 8 | 创新点 | 方法/数据/评价/场景的新意 |
| 9 | 局限性 | 作者写的 + 设计能看出的限制 |
| 10 | 可复刻性 | 代码/数据/参数/训练细节 |
| 11 | 核心要点 | 3–5 条写综述可直接用的短句 |

### Markdown 形状

```markdown
## 1. 文献基本资料

- 标题：……
- 作者：……
- 期刊/会议：……
- 年份：……
- DOI：……
- 类型：……

## 2. 研究内容

……

## 3. 方法

……

……

## 11. 核心要点

- ……
```

### 硬规则

- **禁止大段复制原文**：需要引用时最多 30 字，并带 `[p.N]`；
- 信息缺失写「原文未说明」，不猜；
- 数值只写原文明确出现的值；
- 只使用本文原文与元数据，不引入外部知识；
- 11 个标题顺序固定、文字一致；缺板块由 `parseDeepSections` 补「原文未说明」；
- 精读是独立产物，不改七段卡。

### 方法：三遍读法

| 遍 | 做什么 | 产物 |
|---|---|---|
| 第一遍 5 分钟 | 标题/摘要/图表/结论 | 基本资料、研究内容、结论 |
| 第二遍 1 小时 | 方法、实验、假设 | 方法、样本量、时间、图表解析 |
| 第三遍 深入 | 批判性阅读 | 创新点、局限性、可复刻性、核心要点 |

> 当前 DSH 技能目录里没有现成的「论文精读 skill」。本方案先把三遍读法固化成插件内 prompt/工作流；如果你指定某个 skill 包或模板，再按它的输出格式适配。

## 3. 证据链：多种构建方式

### 3.1 链的数据结构

```json
{
  "id": "ch-xxxxxxxx",
  "title": "极坐标方法在视盘分割中的有效性",
  "question": "极坐标变换是否稳定提升边界指标？",
  "thesis": "在边界区域，极坐标方法优于直角域 baseline",
  "mode": "claim-first|evidence-first|question-first|compare|contradiction|manual",
  "nodes": [
    {"id": "n1", "type": "claim", "text": "……", "paperId": "p-x"},
    {"id": "n2", "type": "evidence", "paperId": "p-x", "evidenceId": "q-y", "page": 5},
    {"id": "n3", "type": "gap", "text": "……"}
  ],
  "edges": [
    {"from": "n2", "to": "n1", "relation": "supports|contradicts|qualifies|derived_from|compares"}
  ],
  "status": "draft|confirmed",
  "createdAt": "……"
}
```

- 证据只存 `paperId + q-id`，不复制原文；
- 每个节点可点回 p.N 高亮；
- 链可插入文稿，插入时生成带引用的段落/提纲。

### 3.2 六种构建方式

| # | 方式 | 输入 | 过程 | 适合 |
|---|---|---|---|---|
| 1 | **论断驱动** claim-first | 精读 claims / 七段卡段落 | 选 claim → 自动找支持/反驳证据 → 确认 | 写综述最常用 |
| 2 | **证据驱动** evidence-first | 选中的 1–N 条引文 | 聚类 → 提炼共同论断 → 生成链 | 读到好句子先收集 |
| 3 | **问题驱动** question-first | 一个研究问题 | 跨论文检索证据 → 分组支持/反驳 → 生成链 | 开题、综述章节 |
| 4 | **对比驱动** compare | 数据集 + 指标 | 从可比组取结果 → 生成对比链/表 | 方法对比 |
| 5 | **矛盾/空白驱动** contradiction | 主题/概念 | 找冲突结果、limitations、未覆盖场景 | 找研究缺口 |
| 6 | **手工构建** manual | 用户拖拽 | 手动连 claim/evidence，标关系 | 精细论证 |

**MVP 先做 1–3**；4–6 放下一阶段。

### 3.3 自动与人工边界

- AI 只**提议**节点和关系，不直接写库；
- 用户点「确认」才落 `chains/`；
- 每条 evidence 必须属于库内已有 q-id；
- 没有证据的 claim 标黄，不允许伪装成 supported；
- 链的 `status=confirmed` 后才能插入文稿。

## 4. 界面

### 4.1 论文页：新增「精读」页签

论文中栏现有：详情 / 七段卡 / 解析稿。

增加 **精读** 页签：

```
┌ 精读 ─────────────────────────────────────────────┐
│ 研究问题 / 缺口 / 一句话贡献                        │
│ 方法链：输入 → 编码 → 解码（每步 p.N）              │
│ 数据 / 指标 / 主结果表（可跳页）                     │
│ 论断表：claim | 类型 | 强度 | 证据 | 状态            │
│ 局限 / 威胁 / 可复现性 / 开放问题                    │
│ [重新精读] [导出 JSON] [用这些 claim 建链]           │
└────────────────────────────────────────────────────┘
```

- claim 行右侧：`p.N`、证据数、支持/部分/无证据；
- 点 claim → 右栏证据/原文定位；
- 不替代七段卡：七段卡是快速摘要，精读是论证素材。

### 4.2 证据链页：独立第三层

在论文库/写作之外增加 **证据链** 入口（可放 `写作` 页右栏，或顶部第四页签）：

```
左：链列表 / 新建
中：链画布（claim/evidence/gap 节点 + 关系边）
右：节点详情 / 证据原文 / p.N
```

- 节点可拖拽；
- 边类型：支持 / 反驳 / 限定 / 推导 / 对比；
- 顶部：`按 claim 建链`、`按问题建链`、`按证据建链`、`手工`；
- 底部：`插入文稿` → 选择 draft → 生成段落/提纲。

### 4.3 写作页联动

写作右栏增加 **证据链** tab：

- 列出已确认的链；
- 「插入论证段」：把 thesis + 支持证据写成一段，引用自动带；
- 「插入提纲」：按链节点生成小标题 + 要点。

## 5. 数据与接口

### 5.1 文件

```
文献库/
├── deepread/<paperId>.json       # 精读结构
├── chains/<chainId>.json         # 证据链
└── drafts/...                    # 不变
```

- 精读与链都是**可重建缓存**，不覆盖卡片；
- 模型/提示词版本写入文件，便于失效重跑；
- 链是用户资产，不随精读重跑删除。

### 5.2 API

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/litkb/deepread/build?id=` | 生成/重跑精读 |
| GET | `/api/litkb/deepread?id=` | 读精读 |
| GET/POST | `/api/litkb/chains` | 列表 / 新建 |
| GET/POST | `/api/litkb/chains/save` | 读 / 保存 |
| POST | `/api/litkb/chains/build` | 按 mode 生成候选链 |
| POST | `/api/litkb/chains/confirm` | 确认落库 |
| POST | `/api/litkb/chains/insert` | 插入文稿 |
| GET | `/api/litkb/chains/export` | 导出 JSON/MD |

### 5.3 Prompt

- `prompts/deep-read.v1.md`：三遍读法 + claim-evidence 矩阵；
- `prompts/chain-claim.v1.md`：claim → 证据；
- `prompts/chain-evidence.v1.md`：证据 → claim；
- `prompts/chain-question.v1.md`：问题 → 跨论文证据。

## 7. 验收

### P4.9

1. 选一篇有解析稿的论文 → 精读；
2. 输出研究问题、方法链、数据/指标/主结果、5–10 条 claims；
3. 每条 claim 至少 1 条 `q-` 证据，点 p.N 能高亮；
4. 无证据的 claim 明确标「无证据」，不编造；
5. 重跑不覆盖手工修改。

### P4.10

1. claim-first：选 1 条 claim → 自动补支持/反驳证据 → 确认；
2. evidence-first：选 2 条引文 → 生成共同 claim → 确认；
3. question-first：输入问题 → 跨 2 篇论文找证据 → 生成链；
4. 链可保存、重开、节点跳 p.N；
5. 链插入文稿 → 生成带引用的段落；反链能看到草稿。

## 8. 风险与取舍

| 风险 | 对策 |
|---|---|
| 模型编造 claim | 只允许 claim 引用库内 q-id；无证据标 unsupported |
| 精读太长 | 固定字段 + 5–10 条 claim，不写长篇 |
| 链太复杂 | MVP 只做 3 种方式、4 种关系；手工后置 |
| 成本 | 精读按篇缓存；链候选不自动落库 |
| 与七段卡重复 | 七段卡保留摘要；精读只做 claim 级 |
| 技能不可用 | 当前无现成精读 skill，先用内置 prompt；指定 skill 后适配 |

## 9. 要你拍板

1. **精读入口**：A 论文中栏新增「精读」页签（推荐）／B 独立顶级页；
2. **证据链入口**：A 写作页右栏 + 论文内入口（推荐）／B 新增顶级「证据链」页签；
3. **MVP 构建方式**：A claim-first + evidence-first + question-first（推荐）／B 只做 claim-first；
4. **AI 自主度**：A 只提议、用户确认后落库（推荐）／B 自动落库再改。

确认后我按顺序：**先补 PRD/SDD/SRS/信息架构/开发计划，再实现 P4.9 精读**。
