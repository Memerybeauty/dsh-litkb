# 产品化交付（v0.11.1）

> 把已经闭环的文献工作台，从“能跑的功能集合”收成“可安装、可上手、可备份、可诊断、可发布”的产品。
> 本文描述 v0.11 的产品化能力；v0.11.1 修复图谱画布 0 高与「从标签建」下拉被裁切；v0.12 的入库自动管线见 [44](44_入库自动管线.md)；功能细节见 [19 功能清单](19_功能清单.md)。

| 项 | 内容 |
|---|---|
| 版本 | **0.11.1** |
| 路由 | 81 → **84**（新增 onboarding / backup / restore） |
| 测试 | **136 项 / 34 个测试文件**，`npm test` 全过 |
| 数据 | 默认 `~/Documents/文献库`；备份与恢复都在本地完成 |
| 形态 | DSH Web 插件；新增 `scripts/install.mjs` 安装器 |

## 1. 为什么做这一版

功能已经覆盖“收文 → 精读 → 证据链 → 研究 → 写作”，但第一次使用仍然要求用户知道：

- 先导入 PDF，再生成卡片，再自动建链，再新建研究；
- 库是一个本地文件夹，升级前要自己备份；
- 出问题时要自己去翻 `index.jsonl`、`cache/` 和日志。

这一版把这三件事收进产品：

| 用户问题 | v0.11 的答案 |
|---|---|
| 我第一次打开，先做什么？ | 工作台欢迎页 + 5 步上手进度，按真实库自动打勾 |
| 换电脑 / 升级 / 误删怎么办？ | 设置里一键下载整库备份，上传恢复，恢复前自动快照 |
| 现在是什么版本、数据在哪、能不能发给别人排查？ | 「关于」显示版本/运行环境/体积，一键复制诊断信息 |
| 怎么装到另一台机器？ | `npm run plugin:install -- --profile desktop` |

## 2. 首次上手

### 2.1 数据来源

`GET /api/litkb/onboarding` 每次按真实库计算，不额外落盘：

```json
{
  "ok": true,
  "version": "0.11.1",
  "library": "/Users/.../Documents/文献库",
  "items": [
    { "key": "paper", "title": "导入第一篇论文", "hint": "PDF 拖拽，或「链接 / DOI」", "done": true, "count": 4, "target": "library" },
    { "key": "card", "title": "生成七段卡", "hint": "打开论文 → 七段卡 → 生成", "done": true, "count": 4, "target": "library" },
    { "key": "chain", "title": "建一条证据链", "hint": "自动建链后在审核队列确认", "done": true, "count": 20, "target": "library" },
    { "key": "theme", "title": "建一个研究并探索", "hint": "工作台 → 新建研究 → 开始探索", "done": false, "count": 0, "target": "theme" },
    { "key": "draft", "title": "写一份文稿", "hint": "写作 → 新建文稿 → 插入引用", "done": false, "count": 0, "target": "writing" }
  ],
  "completed": 3,
  "total": 5,
  "next": "theme",
  "counts": { "papers": 4, "cards": 4, "chains": 23, "confirmedChains": 20, "themes": 0, "drafts": 0 }
}
```

口径：

- `paper` = `index.jsonl` 行数；
- `card` = 有 `card` 摘要的行数；
- `chain` = **已确认**链（草稿不算完成，“确认后才进检索与图谱”与现有边界一致）；
- `theme` = `themes/*.json`；
- `draft` = `drafts/*.md`。

### 2.2 两种形态

| 条件 | 形态 | 内容 |
|---|---|---|
| 库内 0 篇论文 | 欢迎页（大卡） | 产品一句话 + 三步 CTA（导入第一篇 PDF / 浏览论文库 / 新建研究）+ 5 步步骤 |
| 已有论文、未完成 | 进度条（窄卡） | `2/5`、进度条、下一步高亮；点任一步跳到对应模块 |
| 全部完成或已隐藏 | 不渲染 | 不占版面 |
| 完成后从设置重新显示 | 「上手完成」 | 显示 `5/5` 与全部步骤，关闭后再次隐藏 |

- “不再显示”写 `localStorage["litkb.guide.dismissed"] = "1"`；
- 设置 →「重新显示上手引导」清掉标记并广播 `litkb:guide`，工作台立即恢复；
- 完成全部 5 步后自动消失，不打扰长期用户。

### 2.3 交互映射

| 步骤 | 点击后 |
|---|---|
| paper | 打开 PDF 文件选择器 |
| card / chain | 切到论文库 |
| theme | 打开「新建研究」弹层 |
| draft | 切到写作 |

## 3. 数据与备份

### 3.1 备份范围

`GET /api/litkb/backup` 返回 `application/zip`，文件名 `litkb-backup-YYYYMMDD-HHmmss.zip`。

| 包含 | 不包含 |
|---|---|
| `papers/*.pdf` | `settings.json`（PaddleOCR 令牌） |
| `text/`、`blocks/` | `cache/`（页图、检索历史、主题任务快照） |
| `cards/`（含 `.versions/`） | `node_modules/` |
| `translations/`、`deepread/` | |
| `chains/`、`themes/`、`drafts/` | |
| `concepts/`、`exports/` | |
| `index.jsonl`、`tags.json`、`glossary.json`、`topics.json` | |

zip 根目录有 `manifest.json`：

```json
{
  "app": "dsh-litkb",
  "kind": "library-backup",
  "version": "0.11.1",
  "createdAt": "2026-11-10T01:30:00.000Z",
  "roots": ["papers", "text", "cards", "..."],
  "files": 412,
  "bytes": 18432011,
  "excluded": ["settings.json", "cache/"]
}
```

### 3.2 恢复

设置 →「从备份恢复…」选择 zip：

1. 确认框说明会覆盖当前库；
2. 再要求输入「恢复」两个字二次确认；
3. 前端 `POST /api/litkb/restore?confirm=restore`，body 为 zip 原始字节；
4. 服务端校验后覆盖，返回恢复文件数与快照路径；
5. 前端广播 `litkb:data`，工作台与设置重新拉取数据。

安全顺序：

```text
校验 zip
  → 校验 manifest.app/kind
  → 逐条校验路径（拒绝绝对路径、..、空段）
  → 解压到 .litkb-restore-staging-<pid>
  → 把当前库打包到 cache/backups/pre-restore-<时间>.zip
  → 逐目录替换；记录已替换清单
  → 任一步失败：按清单回滚
  → 清理 staging / old
```

### 3.3 语义与限制

- 备份里**有的**目录整体替换；备份里**没有**的目录保留（不会凭空删除）；
- `settings.json` 与 `cache/` 永远不被恢复覆盖，避免覆盖本机令牌与在途缓存；
- 恢复不合并：同一目录不会做文件级 merge；
- 限制：zip 文件 ≤ **512 MB**，解压后 ≤ **2 GB**（防 zip bomb）；
- 覆盖前快照位于 `cache/backups/`，**不会自动清理**；需要时可在文件系统里删；
- 恢复期间再次请求返回 `409 restore_busy`；
- 进程中断：残留的 `.litkb-restore-old/` 会在下次启动时把当前缺失的目录搬回，再清理临时目录；
- 错误码：`confirm_required`(428)、`too_large`(413)、`bad_zip/bad_entry/bad_manifest/no_data`(422)。

### 3.4 设置页展示

「数据与备份」显示论文 / 卡片 / 证据链 / 研究 / 文稿数量、数据体积、最近快照（文件名、时间、大小、快照数），并提供：

- 「下载整库备份」：直接下载 zip；
- 「从备份恢复…」：上传 zip；
- 恢复结果与快照路径提示。

## 5. 安装与升级

### 5.1 安装器

```bash
npm run plugin:install -- --profile desktop
```

脚本 `scripts/install.mjs`：

1. 读 `package.json` 版本，找 `dsh-litkb-<version>.tgz`，没有就 `npm pack`；
2. 定位 `~/.dsh/profiles/<profile>/package.json`；
3. 写入 `dependencies["dsh-litkb"] = "file:<tgz 绝对路径>"`；
4. 确保 `dsh.profile.bundles` 含 `dsh-litkb`；
5. 备份原 `package.json` 为 `.bak-litkb`，执行 `pnpm install --prefer-offline`；失败自动还原；
6. 打印重启与健康检查步骤。

选项：

| 参数 | 说明 |
|---|---|
| `--profile <name>` | profile 名，默认 `desktop`；也接受绝对路径 |
| `--link` | 开发模式，安装当前工作区 `link:`，不打包 |
| `--tgz <path>` | 指定安装包 |
| `--dry-run` | 只打印计划，不改文件 |
| `--pnpm <path>` | 指定 pnpm |
| `--skip-install` | 只改 manifest，不跑 pnpm（离线/自定义安装） |

### 5.2 升级流程

```bash
npm run build && npm test
npm run plugin:install -- --profile desktop
# 完全退出 DSH 再启动
# Cmd+Shift+R
curl http://127.0.0.1:<端口>/api/litkb/health   # "version":"0.11.1"
```

升级前建议在设置里下载一次整库备份；恢复时优先用最新快照回滚。

### 5.3 回滚

- 代码：`git checkout v0.10.0` 或安装上一版 tgz；
- 数据：设置 → 从备份恢复，选择升级前的 zip；恢复前会自动再快照一次；
- 不要手动删 `cards/`、`chains/`、`drafts/`、`themes/`。

## 6. 验收清单

### 6.1 上手

1. 新建一个空库：`LITKB_LIBRARY=/tmp/litkb-empty` 重启；
2. 打开工作台：出现欢迎页，三步 CTA 可点；
3. 导入 PDF 后：变为「1/5」进度条，下一步高亮「生成七段卡」；
4. 点「不再显示」后刷新：不再出现；
5. 设置 →「重新显示上手引导」：工作台立即恢复。

### 6.2 备份与恢复

1. 设置 →「下载整库备份」，得到 zip；
2. 解压检查：有 `manifest.json`、`index.jsonl`、`cards/`，无 `settings.json`、`cache/`；
3. 改一篇论文标题或删一个文稿；
4. 设置 →「从备份恢复…」上传 zip，输入「恢复」；
5. 数据回到备份时状态；`cache/backups/pre-restore-*.zip` 存在；
6. 再次恢复同一 zip：仍成功，说明快照不阻断。

### 6.3 关于与诊断

1. 设置 →「关于」：版本、Node、体积正确；
2. 「复制诊断信息」：粘贴包含版本、库路径、计数；
3. 页脚显示 `v0.11.1`。

### 6.4 工程门

```bash
npm run verify     # check + lint + format:check + test
npm run coverage   # 覆盖率门槛 70/65
npm pack           # dsh-litkb-0.11.1.tgz
```

## 7. 明确边界

| 项 | 现状 |
|---|---|
| 云同步 / 定时备份 | 不做；备份是手动下载的本地 zip |
| 多用户 / 权限 | 单机单用户 |
| 备份加密 | 不做；zip 是明文，请自行保管 |
| 令牌迁移 | `settings.json` 不进入备份，换机需重新填 PaddleOCR 令牌 |
| 恢复合并 | 不做文件级 merge；按目录整体替换 |
| 自动清理快照 | 不做；`cache/backups/` 需手动清理 |
| 自动更新 | 不做；升级走安装器 + 重启 |
