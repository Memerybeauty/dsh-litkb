## 1. 场景与目标

### 1.1 用户故事

> 我研究「多模态大模型在医学影像诊断中的应用」。我把它拆成几条细分描述：
> ① 融合方式 ② 数据集与标注规模 ③ 评测指标与临床验证 ④ 局限性与失败模式。
> 我希望系统在库里找出每条细分描述对应的论文和原文证据，**每条细分描述生成一条证据链**，我再逐条审核。

### 1.2 与现有三种建链的区别

| 方式 | 论点来源 | 证据来源 | 现有实现 |
|---|---|---|---|
| 论点先行 | 论文精读的一句话 | 该论文 | `proposeFromClaim` |
| 证据先行 | 选中证据后回填 | 选中证据 | `proposeFromEvidence` |
| 问题先行 | 检索 + 模型提炼 | 检索命中 | `proposeFromQuestion` |
| 跨论文对比 | 两篇论文各一句 | 两篇 | `autoCrossPaperDrafts` |
| **主题建链（新）** | **用户的研究主题细分描述** | **库内多篇匹配证据** | 无 |

关键差异：**claim 是用户的，跨论文取证**。所以不能复用 `autoChainDrafts`（它从论文里抽 claim），要新写一个"主题 → 多篇证据"的合成器，但节点锚定、去重、审核全部复用现有能力。

### 1.3 目标 / 非目标

**目标**
1. 主题 CRUD（标题、描述、细分描述、可选关键词/标签预筛）；
2. 每条细分描述能"预览匹配"：命中哪些论文、哪些 q-id、分数与命中词；
3. 一键为全部（或选中）细分描述生成 draft 链；
4. 缺口显式：没有证据的细分描述标「缺口」，不硬凑；
5. 审核复用现有队列，确认后才进检索/图谱；
6. 无模型可用（规则匹配），有模型可增强。

**非目标（本期不做）**
- 不做主题自动发现/聚类（后续可做）；
- 不做向量检索（本地优先原则不变）；
- 不做整库主题报告导出（可排后续）；
- 不覆盖人工已确认的链。

## 3. 命名与入口（已定）

### 3.1 命名冲突

现有 `paper.topics` 是**标签**（扁平分类，如「医学影像」），`chain.topic` 也复用了它。如果新概念也叫 `topics`，代码和文档会长期混淆。

**已定分层**：

| 层 | 名字 |
|---|---|
| 顶层页签 | **研究工作台** |
| 工作台里的研究对象 | **主题**（单个叫「研究主题」） |
| 代码/数据 | `themes/`、`themeId`、`t-xxxxxxxx`，模块 `lib/themes.js` |
| 与标签的关系 | 主题可**绑定标签做预筛**（`theme.tags`），但两者不是一回事 |

文案上明确：**标签是"这篇论文属于哪类"，主题是"我要论证什么"**。

### 3.2 入口：顶层「研究工作台」（已定）

顶层新增页签 **研究工作台**，放在「论文库」之后、「横向精读」之前。它不是主题列表页，而是把 **定义主题 → 匹配 → 建链 → 审核 → 写作** 收在同一个工作面：

```text
研究工作台（顶层页签）
├── 概览条：主题数 / 细分描述 / 已确认链 / 待审 / 缺口
├── 视图 1 主题（默认）
│   ├── 左：主题列表（完成度徽标）
│   └── 右：主题头 + 细分描述卡片（匹配数、链状态、缺口、看链/重跑/编辑）
├── 视图 2 覆盖矩阵（细分描述 × 论文）
├── 视图 3 待审草稿（origin=topic，可跳现有审核队列）
└── 出口：看链 → ChainDialog（复用）；插入文稿 / 存为文稿（复用写作链路）
```

页签从 5 个变 6 个，窄屏需验证；若溢出，优先压缩文案（「工作台」）而不是新增二级菜单。

## 4. 数据模型

### 4.1 主题文件

`文献库/themes/<id>.json`（一份一主题，原子写；列表用目录扫描，不另建索引）

```json
{
  "id": "t-1a2b3c4d",
  "title": "多模态大模型在医学影像诊断中的应用",
  "description": "关注融合方式、数据规模、临床验证与失败模式，用于综述第二章。",
  "tags": ["医学影像", "多模态"],
  "facets": [
    {
      "key": "f1",
      "title": "多模态融合方式",
      "description": "早期融合、晚期融合、跨模态注意力的差异与取舍",
      "keywords": ["fusion", "融合", "cross-attention"],
      "mode": "compare",
      "enabled": true
    },
    {
      "key": "f2",
      "title": "数据集与标注规模",
      "description": "用了哪些公开/私有数据集，样本量与标注方式",
      "keywords": ["dataset", "数据集", "标注"],
      "mode": "compare",
      "enabled": true
    }
  ],
  "createdAt": "2026-11-09T10:00:00.000Z",
  "updatedAt": "2026-11-09T10:00:00.000Z",
  "lastRun": {
    "runId": "run-theme-...",
    "at": "2026-11-09T10:05:00.000Z",
    "matcher": "theme-match.v1",
    "model": null
  }
}
```

**字段说明**
- `facets[].key`：`f1/f2/...`，创建时生成，**编辑标题不改 key**（链靠它做幂等）；
- `facets[].keywords`：可空。非空时做**硬过滤**（必须命中至少一个），防止主题漂移；
- `facets[].mode`：`compare`（默认，多篇并置）或 `verify`（找支持/反驳）；
- `facets[].enabled`：临时关闭某条细分描述；
- 每条 facet 的**匹配结果与链状态不落主题文件**，由链的 `provenance` 反查，避免两份真源。

### 4.2 链的扩展（向后兼容）

生成的链沿用 `normalizeChain`，只加三处：

```json
{
  "origin": "topic",
  "topic": "多模态大模型在医学影像诊断中的应用",
  "provenance": {
    "themeId": "t-1a2b3c4d",
    "facetKey": "f1",
    "runId": "run-theme-...",
    "matcher": "theme-match.v1",
    "query": "多模态融合方式 早期融合、晚期融合……",
    "tokens": ["多模态", "融合", "……"],
    "model": null
  }
}
```

- `origin` 枚举加 `'topic'`（`lib/chains.js:690`、检索展示、审核筛选各改一处）；
- `claim.text` = facet 的论点句（≤240 字，超了截断并 warning）；`claim.source = 'topic'`；
- 节点仍走 `normalizeNode`，非法 q-id 直接丢并计数。

### 4.3 新增目录

```text
文献库/
└── themes/
    ├── t-1a2b3c4d.json
    └── t-5e6f7a8b.json
```

无迁移、无破坏；备份只需带上 `themes/`。

## 5. 匹配算法

### 5.1 文档源

对每个 facet 建查询，对两类文档打分：

| 文档 | 内容 | 权重 |
|---|---|---|
| 证据文档 | 卡片 `evidence[].quote` | quote ×3、论文标题 ×2、标签 ×1 |
| 论点文档 | 精读 11 板块的句子（带 q-id 的才算） | 句子 ×3、论文标题 ×2 |

> 只索引"有卡片"的论文；draft 链不进文档源，避免自我强化。

### 5.2 打分

```text
score = bm25(queryTokens, doc)
      + 2.0 × conceptOverlap(facet, paper)     // 方法/数据集/指标命中数
      + 1.5 × tagMatch(facet, paper.topics)    // 主题绑定标签命中
      - 1.5 × (该论文已被本 facet 取满 2 条)
```

**过滤**
1. 硬过滤：`facet.keywords` 非空时，至少命中一个（归一化后子串或分词命中）；
2. 相对阈值：保留 `score ≥ 0.4 × top1` 且 `score ≥ 1.5`；
3. 每篇最多 2 条，每条 facet 最多 6 篇 / 8 条证据；
4. 已被**其他主题已确认链**用过的 q-id 不排除，但命中时加 warning「已被主题 X 引用」。

### 5.3 伪代码

```js
function matchFacet(theme, facet, options) {
  const query = [facet.title, facet.description, ...(facet.keywords || [])].join(' ')
  const tokens = tokenize(query)
  const docs = buildThemeCorpus({ tags: theme.tags, excludeDrafts: true }) // evidence + claims
  const hits = []
  for (const doc of docs) {
    if (!passesKeywordFilter(facet, doc)) continue
    const score = bm25Score(tokens, doc) + conceptBoost(facet, doc.paperId) + tagBoost(theme, doc.paperId)
    if (score <= 0) continue
    hits.push({ ...doc, score: round(score), matched: matchedTerms(tokens, doc) })
  }
  const ranked = takeDiverse(hits.sort(byScore), { perPaper: 2, papers: 6, evidence: 8 })
  const top = ranked[0]?.score || 0
  return ranked.filter((hit) => hit.score >= Math.max(1.5, top * 0.4))
}
```

### 5.4 复杂度

30 篇 / 300 证据 / 5 条 facet：一次匹配约 5 × 300 次 BM25 打分，目标 **< 300ms**（现有检索 18–21ms，量级可接受）。超过 500 篇再考虑建持久索引。

## 6. 建链规则

### 6.1 一条 facet = 一条链

```text
claim.text      = facet 的论点句（默认 facet.title，可编辑）
nodes           = 匹配结果 top 2–4 条证据，跨论文，每篇 ≤2
nodes[].relation = cueRelation(quote)；compare 模式下默认 compares
confidence      = 0.45 + 0.1×min(4, 论文数) + 0.15(有 block) + 0.1(关键词命中) + 0.1(分数比 >0.7)
status          = draft
warnings        = 单篇支撑 / 低分匹配 / 无 block / 被其他主题引用
```

### 6.2 去重与重跑（关键）

- 链的 `provenance.themeId + facetKey` 是幂等键；
- 重跑时：**已有 draft** → 原地更新（`saveChain({...existing, nodes, confidence})`），不新增；
- 已有 **confirmed** → 不覆盖，另生成一条 draft 并提示「已有确认链，本次为补充草稿」；
- 跨主题同一 q-id 允许复用（图谱汇聚是特性，不是 bug）。

### 6.3 缺口

匹配为空或全部低于阈值：**不建空链**，facet 记 `gap`，返回原因（无关键词命中 / 分数过低 / 该主题标签下没有论文）。UI 显示「缺口：建议补标签、放宽关键词或先导入论文」。

### 7.2 三个视图的切换

- **主题**（默认）：上面的主视图；
- **覆盖矩阵**：本主题下 细分描述 × 论文 的表格（● 有证据 / ○ 弱命中 / 空 缺口），点格子可跳到对应证据；
- **待审草稿**：`origin=topic` 的 draft 列表，可就地确认/拒绝，也可跳现有审核队列。

切换放在主题头右侧的分段控件（Segmented），不新增二级页签。

### 7.3 新建/编辑弹窗

- 工作台级：标题、描述（可选）、绑定标签（可选，多选）、年份范围（可选）；
- 细分描述：逐行编辑，一行 `标题｜描述｜关键词`，也可点「AI 帮我拆」由模型生成 3–6 条（无模型时给模板）；
- 保存即写 `themes/<id>.json`，列表与概览条即时刷新。

### 7.4 匹配预览

点「匹配预览」→ 每条细分描述就地展开命中列表：论文、q-id、页码、引文前 80 字、分数、命中词、概念命中。**不写库**。用于调关键词、调阈值；每条命中都可点开原文。

### 7.5 生成与审核

- 「全部生成」→ 概览条下方进度（复用任务队列），逐 facet 建 draft；
- 完成后细分卡片显示「草稿 1 条 · 看链」；
- 审核走现有队列（`/chains/review`），加 `origin=topic` 筛选与「主题」徽标；
- 确认后才进检索召回与知识库图。

### 7.6 工作台的出口（为什么叫"工作台"）

不只是看，还要能往下走：

| 出口 | 复用 |
|---|---|
| 看链 / 改链 | `ChainDialog`（`40-chain.js`） |
| 插入文稿 | `appendChainToDraft`（`chains.js`） |
| 存为文稿 | 写作页现有链路 |
| 去论文 / 去原文 | `onOpenPaper` / p.N 跳转 |

## 10. 无模型降级与模型增强

| 能力 | 无模型 | 有模型 |
|---|---|---|
| 拆分细分描述 | 模板（研究对象/方法/数据/指标/局限） | 3–6 条，带关键词 |
| 匹配 | BM25 + 概念 + 标签 | 可选：对 top 20 候选做相关性重排 |
| 论点句 | 直接用 facet.title | 精炼成一句可辩论的 claim（≤120 字） |
| 关系判断 | 线索词规则 | 可选：对矛盾对复核 |
| 复核 | 无 | 可选：逐条判断"引文是否支持该 claim" |

**红线**：模型只能**重排/改写/判断**，不能新增 q-id；节点一律走 `normalizeNode` 白名单校验，与现有链路一致。

## 11. 边界与风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 误召回 | 主题词在论文里只是顺带一提 | 关键词硬过滤 + 相对阈值 + 必须人工审核 |
| 单一论文撑全链 | 6 条证据同源 | 每篇上限 + 「单篇支撑」warning + 矩阵提示 |
| 链库膨胀 | 每次重跑新增一条 | `themeId+facetKey` 幂等更新 |
| 主题与标签混淆 | 用户不知道用哪个 | 文案区分；主题可绑标签但标签不叫主题 |
| 已确认链被覆盖 | 人工成果丢失 | confirmed 不覆盖，另起 draft |
| 页签过多 | 窄屏挤压 | 6 个页签先量宽度，溢出则收进「更多」 |
| BM25 短文本偏差 | 引文只有一两句 | 同时索引精读句子，标题加权 |

### 12.2 人工验收

1. 真实库建 1 个主题、4 条细分描述；
2. 「匹配预览」每条至少能解释命中原因（命中词可见）；
3. 生成后 ≥3 条 draft，节点 q-id 全部可跳原文；
4. 缺口 facet 不产生空链，提示可操作；
5. 确认 1 条后：检索能召回、知识库图出现、写作可引用；
6. 重跑同一主题：draft 更新不重复，confirmed 不动。
