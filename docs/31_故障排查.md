# 故障排查

## 1. 新接口 404 / 工具不出现

- 原因：只刷新页面，服务端仍是旧进程；
- 检查：`GET /api/litkb/health` 的 version；
- 处理：完全退出 DSH（Cmd+Q）再打开，然后 `Cmd+Shift+R`。

## 2. 页面暗底暗字 / 弹窗透明

- 原因：客户端主题令牌没跟随宿主；
- v0.1.2 已通过 `litkb-theme-light/dark` 显式主题类修复；
- 仍有问题：强制刷新；确认没有多个 DSH 进程/旧端口。

## 3. 横向精读表格只显示几行

- v0.28.3 已修 `litkb-compareTable` 类名冲突；
- v0.1.2 源码中表类为 `litkb-compareGrid`；
- 若仍裁切，确认加载的是 0.1.2 客户端。

## 4. 概念图谱看不到

- 预期行为：v0.28.4 起 UI **暂时隐藏**；
- 数据与 `/graph` 接口保留，代码 `ConceptGraphPanel` 仍在。

## 5. 自动建链提示“没有精读”

- v0.27.2 起无精读会用七段卡兜底；
- 若仍报错，确认该论文至少有七段卡；
- 没有卡/精读时提示 `no_source` 是预期。

## 6. 链接导入没有 PDF

- 只接受开放可访问的 PDF；
- DOI 有元数据但无开放 PDF 时返回 `no_pdf`；
- 处理：下载 PDF 后本地导入，或直接贴 `citation_pdf_url`/PDF 链接。

## 7. Git push HTTP 400

- 本机曾因 HTTP 缓冲导致 5MB 首推失败；
- 可设置：`git config http.postBuffer 52428800`，再 `git push`。

## 8. 研究工作台

- **页签不见 / `/api/litkb/themes` 404**：客户端是新的、服务端是旧进程；完全重启 DSH；
- **匹配不到证据**：先看细分描述的关键词是否过窄（关键词是硬过滤）；库里至少要有七段卡；
- **生成任务一直排队/失败**：`GET /api/litkb/themes/jobs?id=` 看 `status/errors`，失败信息在 `errors[].message`；
- **提纲没写进文稿**：`/themes/outline` 不带 `mode` 只预览；写入要 `mode=new/append/replace`；
- **确认后检索不到主题链**：确认只改 `status`，检索需重启后重新查询；草稿不进检索。

## 9. 备份与恢复

- **下载备份 404**：服务端还是 0.10 或更早；重启 DSH，确认 `/health` 是 0.14.0；
- **恢复提示「不是文献工作台备份」**：zip 里没有 `manifest.json`，或 `app/kind` 不匹配；不要改 manifest；
- **恢复提示「备份包含非法路径」**：zip 被二次打包或含 `../`；解压后重新压缩根目录内容；
- **恢复提示 `restore_busy`**：上一个恢复还没结束；等待后再试；
- **恢复后想回退**：用 `cache/backups/pre-restore-<时间>.zip` 再恢复一次；
- **令牌丢了**：`settings.json` 不进备份，重新填 PaddleOCR 令牌即可；
- 恢复不会删除备份里没有的目录；如需彻底清空，先备份再手动处理库目录。

## 10. 上手引导

- **不出现**：库里有论文且 5 步已完成时自动隐藏，属预期；或之前点过「不再显示」；
- **重新显示**：设置 →「上手引导」→「重新显示上手引导」；
- **进度不动**：里程碑按 `index.jsonl`、卡片、已确认链、`themes/`、`drafts/` 实时计算；草稿链不算完成。

## 11. 证据链图空白 / 标签下拉被裁

- **证据链图只有工具栏和图例、画布空白**：v0.11.0 的高度链问题，v0.11.1 已修；确认 `/health` 是 0.14.0，强刷页面；
- **工作台「从标签建」下拉只显示到一半**：v0.11.0 的工作台页 `overflow:hidden` 裁切，v0.11.1 已改为可见 + 菜单限高滚动；
- 若仍复现：先强刷，再看控制台是否有 Cytoscape 加载错误（`图引擎加载失败` 会显示在画布上）。

## 12. 入库自动处理

- **导入后没有出现自动处理条**：设置 →「入库自动化」是否被关闭；或服务端仍是旧版本（`/health` 应为 0.14.0）；
- **只有原文解析，卡片/精读显示「跳过」**：宿主没有可用模型或未选默认模型；在 DSH 设置里选模型后，点论文行「补全」；
- **一直停在「原文解析」**：PaddleOCR 可能较慢或令牌失效；看顶部步骤文案，必要时在设置里停用 PaddleOCR，改用 pdf.js 后点「补全」；
- **任务不见了**：任务只在内存，DSH 重启后丢失；已落盘步骤不会丢，点「补全」从缺失步骤继续；
- **想对旧论文补齐**：论文行 hover →「补全」，已有产物会自动跳过；
- **7 段卡/精读失败**：先确认模型可用；失败信息会显示在任务条和 `/api/litkb/diag` 的 `ingest` 里。

## 13. 删除论文

- **找不到删除入口**：打开论文详情（论文库中间面板），头部状态徽标右侧「删除」；
- **提示需要确认**：先确认影响面，再输入「删除」两个字；两步都通过才执行；
- **删除后文献链还在**：只删除“全部引用该论文”的链；跨论文链会移除该论文节点后保留；被删论文的节点不会再出现；
- **文稿里引用变红/缺失**：文稿不会自动改写，引用校验会显示缺失；需要手动删除对应引用；
- **想恢复**：删除不可恢复；请用「设置 → 数据与备份」的整库备份恢复；
- **删除失败**：检查论文是否已被其他进程删除；刷新后重试；
- **提示 409 / 正在自动处理**：等原文解析、七段卡或精读任务完成，或在设置里关闭入库自动化后再删。

## 14. 模型与 API Key

- **报 `no API key for provider route "deepseek-official"`**：
  - 设置 →「模型」勾选「文献工作台固定使用 DeepSeek」，模型选 `deepseek-v4-pro` 或 `deepseek-flash`；
  - 密钥通过 DSH 凭据服务写入 `DEEPSEEK_API_KEY`（Models 页或 `.credentials.yaml`），不要写进库设置；
  - 改完**完全重启 DSH**，因为凭据服务在启动时加载；
- **报 unsupported reasoning effort**：v0.14 已把 DeepSeek V4 的 `off` 自动降为 `low`；确认加载的是 0.14.0；
- **想改回跟随 DSH 默认模型**：设置 →「模型」取消勾选，保存；
- **看当前实际路由**：设置 →「模型 → 当前模型」，显示 `provider / model`；
- **环境变量覆盖**：`LITKB_LLM_PROVIDER` / `LITKB_LLM_MODEL` 优先级最高，适合临时排查。

## 15. 查看日志

- DSH 启动日志应有 `[dsh-litkb] plugin loaded v0.14.0`；
- 以及 `12 agent tools registered`；
- 端口以当前 Web GUI URL 为准，不要用旧端口。
