# 文献工作台：个人工作台 + 论文库 + 写作

| 项 | 内容 |
|---|---|
| 状态 | **已实现（v0.2.5：总览 + 三视图）** |
| 入口 | 顶层页签 **研究工作台** |
| 结构 | **总览**（所有研究）→ **单个研究**（研究内容 / 论文 / 写作） |
| 场景 | 声明研究主题 → 库内匹配论文 → 按细分描述建证据链 → 形成研究内容 → 写作 |
| 原则 | 证据可溯、受控词表、失败显式、人审闭环 |

> v1 → v2 的变化：去掉工作台内的「主题 / 覆盖矩阵 / 待审」三视图，收敛为 **总览 + 研究页**。
> 覆盖矩阵、待审并入研究页；总览只回答"我有哪些研究、进展到哪"。

---

## 1. 场景

### 1.1 用户故事

> 我研究「多模态大模型在医学影像诊断中的应用」，拆成 4 条细分描述：融合方式 / 数据集规模 / 临床验证 / 失败模式。
> 打开研究工作台，看到这条研究：库里匹配到 4 篇论文、3 条链已确认、1 条细分还是缺口。
> 点进去，研究内容、这 4 篇论文、以及这篇综述的初稿，都在同一个页面里。

### 1.2 一个"研究"就是三样东西

| 组成 | 内容 | 来源 |
|---|---|---|
| **研究内容** | 细分描述、每条细分描述的证据链、综合结论、缺口 | 主题 + 匹配 + 建链 |
| **符合要求的论文** | 主题下匹配到的论文列表（可手动加入/移出） | 匹配结果 + 人工增删 |
| **论文写作** | 绑定的文稿：提纲/初稿、引用、参考文献 | 已确认链 + 写作页 |

三者互相引用：写作里的引用来自链，链的节点来自论文，论文的命中理由来自细分描述。

### 1.3 非目标

- 不做主题自动发现/聚类；
- 不做向量检索；
- 不自动生成整篇成稿（只到提纲 + 引用，段落扩写走现有 AI 扩写）；
- 不覆盖人工确认过的链。

## 2. 与现有能力的关系

| 现有能力 | 在新结构里的位置 |
|---|---|
| 论文库 / 标签 / 原文 | 不动；论文详情仍从研究页可跳 |
| 七段卡 / 精读 / 证据 | 研究内容的数据源 |
| 证据链（四种建链 + 审核） | 研究内容的核心；新增 `origin=topic` |
| 知识库图 | 不动；主题链确认后自然进图 |
| 检索 | 不动；主题链可被检索召回 |
| 写作 | 每个研究绑定一份文稿，复用现有 CRUD/引用/参考文献 |
| 横向精读 | 不动，研究页的论文列表可跳横向对比 |
| 概念图谱 / 可比组 | 不动 |

│   ├── 研究卡片总览

## 4. 研究内容

### 4.1 细分描述 → 证据链

- 一个研究 3–6 条细分描述（facet）；每条可配关键词、模式（compare / verify）；
- 每条细分描述做一次库内匹配，合成**一条 draft 链**（claim = 细分描述，证据跨论文）；
- 状态：`未匹配` → `匹配到证据` → `草稿链` → `已确认` / `缺口`；
- 缺口不建空链，给原因和可操作建议。

### 4.2 综合结论（研究内容的结果）

- 只从**已确认链**合成：每条链一句结论 + 引用；
- 无模型时：结构化列表（细分描述 → 链 claim → 引用）；
- 有模型时：写成 3–5 段概述，仍受 q-id 白名单约束；
- 可手改，存 `theme.summary`；改过的不被重跑覆盖。

### 4.3 覆盖矩阵（v0.2.3 暂不展示）

细分描述 × 论文的小表：● 有证据、○ 弱命中、空 缺口。放在研究内容底部，不单独成页。

## 5. 符合要求的论文

匹配结果默认全收，允许人工干预：

| 状态 | 含义 | 存储 |
|---|---|---|
| matched | 有细分描述命中 | 派生（不落盘） |
| included | 手动加入（没命中但我要用） | `theme.papers.include` |
| excluded | 手动移出（命中了但不相关） | `theme.papers.exclude` |

列表列：论文 / 年份 / 匹配分 / 命中细分 / 证据数 / 链数 / 操作（看原文、加横向对比、移出）。

"符合要求"的判定：`(派生命中 ∪ included) − excluded`。移出的论文不影响已生成的链，只影响后续匹配。

## 6. 论文写作

- 每个研究绑定**一份文稿** `draftId`；首次点「开始写作」时创建，标题默认「主题名 · 初稿」；
- 「生成提纲」：按细分描述生成 H2，每条已确认链生成一条论点句 + 引用 `[[p-xxx#^q-id|作者 年, p.N]]`；
- 无模型：纯结构化提纲（标题 / 论点 / 引用），可直接在写作页编辑；
- 有模型：可对单段做「按证据扩写」，复用现有 `drafts/assist` 链路；
- 不自动写完整初稿；引用、参考文献、反链全部沿用写作页现有能力；
- 研究页显示写作进度：字数、引用数、已确认链覆盖率（有链但没被引用的会提示）。

## 7. 数据模型

### 7.1 研究文件

`文献库/themes/<id>.json`

```json
{
  "id": "t-1a2b3c4d",
  "title": "多模态大模型在医学影像诊断中的应用",
  "description": "用于综述第二章，关注融合、数据、验证、失败模式。",
  "tags": ["医学影像", "多模态"],
  "facets": [
    {
      "key": "f1",
      "title": "多模态融合方式",
      "description": "早期融合、晚期融合、跨模态注意力的差异与取舍",
      "keywords": ["fusion", "融合", "cross-attention"],
      "mode": "compare",
      "enabled": true
    }
  ],
  "papers": {
    "include": ["p-3f2a1b0c"],
    "exclude": [],
    "lastMatch": { "at": "2026-11-09T10:00:00.000Z", "papers": 4, "hits": 12 }
  },
  "draftId": "d-9a8b7c6d",
  "summary": { "text": "", "updatedAt": null, "model": null },
  "createdAt": "2026-11-09T10:00:00.000Z",
  "updatedAt": "2026-11-09T10:00:00.000Z",
  "lastRun": { "runId": "run-theme-...", "at": "...", "matcher": "theme-match.v1" }
}
```

- `facets[].key` 创建时生成，改标题不改 key（链的幂等键）；
- `papers.include/exclude` 是人工覆盖，派生命中不落盘；
- `summary.text` 非空表示人工改过，重跑不覆盖；
- 链状态不存主题文件，由链的 `provenance.themeId + facetKey` 反查。

### 7.2 链扩展

```json
{
  "origin": "topic",
  "topic": "多模态大模型在医学影像诊断中的应用",
  "provenance": {
    "themeId": "t-1a2b3c4d",
    "facetKey": "f1",
    "runId": "run-theme-...",
    "matcher": "theme-match.v1",
    "query": "多模态融合方式 早期融合……",
    "model": null
  }
}
```

`origin` 枚举加 `'topic'`；claim 仍 ≤240 字；节点走 `normalizeNode`。

### 7.3 目录

```text
文献库/
├── themes/<id>.json          # 研究
├── chains/<id>.json          # 主题链（origin=topic）
└── drafts/<id>.md            # 研究绑定的文稿
```

无迁移；备份带上 `themes/`。

## 8. 匹配与建链（规则不变，收敛表述）

### 8.1 匹配

```text
query = facet.title + facet.description + facet.keywords
文档 = 卡片引文（quote×3、标题×2、标签×1）+ 精读带 q-id 的句子
score = BM25 + 2.0×概念命中 + 1.5×标签命中 − 1.5×(该篇已取满 2 条)
```

- 关键词非空时硬过滤（至少命中一个）；
- 相对阈值：`score ≥ 0.4×top1` 且 `≥ 1.5`；
- 每篇 ≤2 条，每条细分描述 ≤6 篇 / 8 条证据；
- 只索引有卡片的论文；draft 链不进文档源。

### 8.2 建链

```text
claim  = 细分描述（可编辑，≤240 字）
nodes  = top 2–4 条证据，跨论文
关系    = cueRelation(引文)；compare 模式默认 compares
状态    = draft（全部人工审核）
```

- 幂等：`themeId + facetKey` 已有 draft → 原地更新；已有 confirmed → 不覆盖，另起 draft 并提示；
- 缺口：不建空链，返回原因；
- 全部进现有审核队列（`/chains/review` 加 `origin=topic` 筛选）。

```text

┌ 链列表 ────────┬ 链详情 ─────┐      ┌ 结论 ──────┬ 支撑链 ─────┐
│ 融合方式 [草稿] │ 论点         │      │ 生成/编辑   │ 融合方式     │
│  └ 极坐标…      │ 证据节点     │      │ 正文…      │  论点 + 证据 │
│ 数据集 [缺口]   │ [确认][拒绝] │      │            │ [在链中查看] │
└────────────────┴─────────────┘      └────────────┴─────────────┘
```

- 证据链点一条 → 右侧详情，可确认/拒绝、插入写作、跳原文/精读；
- 研究结论只从**已确认链**生成；右侧列出来源链，点「在证据链中查看」跳转。

### 9.5 状态保持

- 工作台、论文库、写作三个模块常驻（隐藏不卸载）；
- 从工作台打开论文再回来，仍在同一研究、同一视图（参考论文/证据链/结论）和原滚动位置；
- 论文阅读页的选中论文也保留。

## 10. API（11 条）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/litkb/themes` | 总览聚合（每行：论文数、链数、缺口、待审、写作状态） |
| GET | `/api/litkb/themes/read?id=` | 研究详情（facets、论文、链、文稿、summary） |
| POST | `/api/litkb/themes/save` | 新建/更新（facets 全量覆盖，key 保留） |
| POST | `/api/litkb/themes/delete` | 删除研究（链与文稿保留，提示） |
| POST | `/api/litkb/themes/match` | 匹配预览（不写库） |
| POST | `/api/litkb/themes/chain` | 生成 draft 链（全部或指定 facetKeys），返回 job |
| GET | `/api/litkb/themes/jobs?id=` | 任务进度 |
| POST | `/api/litkb/themes/papers` | 手动加入/移出论文 |
| POST | `/api/litkb/themes/outline` | 生成提纲/初稿并绑定文稿 |
| POST | `/api/litkb/themes/summary` | 生成/保存综合结论（有模型增强） |
| POST | `/api/litkb/themes/suggest` | AI 拆细分描述（可选） |

`/chains/review` 加 `origin` 过滤；`/drafts/*` 不改。

## 11. 无模型降级

| 能力 | 无模型 | 有模型 |
|---|---|---|
| 拆细分描述 | 模板（对象/方法/数据/指标/局限） | 3–6 条 + 关键词 |
| 匹配 | BM25 + 概念 + 标签 | 可对 top 20 重排 |
| 综合结论 | 已确认链的结构化列表 | 3–5 段概述 |
| 提纲 | H2 + 论点句 + 引用 | 可加过渡句 |
| 段落扩写 | 不做 | 复用 `/drafts/assist` |

红线不变：模型不能新增 q-id，节点一律走白名单校验。

## 12. 风险

| 风险 | 对策 |
|---|---|
| 研究页信息过载 | 三段折叠，默认只展开研究内容；论文/写作按需 |
| 写作与链脱节 | 显示「链覆盖率」；未被引用的链标灰提示 |
| 误召回 | 关键词硬过滤 + 阈值 + 全量审核 |
| 链库膨胀 | `themeId+facetKey` 幂等；confirmed 不覆盖 |
| 总览数字失真 | 全部从链与文稿实时聚合，不缓存计数 |
| 窄屏 | 研究页单列堆叠；总览表格横向滚动 |

## 16. 原定决策

| 决策 | 结论 |
|---|---|
| 入口 | 顶层「研究工作台」，两级：总览 → 研究页 |
| 研究页三段 | 研究内容 / 论文 / 写作 |
| 主题来源 | 手动 + 「AI 帮我拆」（无模型给模板） |
| 写作深度 | **提纲 + 引用**，不自动写初稿；段落扩写走现有 AI 扩写 |
| 综合结论 | **手动触发**，手改后不被重跑覆盖 |
| 审核 | 全部 draft + 人工审核，确认后才进检索与图谱 |
| 命名 | 界面「研究工作台 / 研究」，代码 `themes` |

无遗留待确认项。任务拆解与排期见 [35 开发计划](35_研究工作台开发计划.md)；下一步 P5.0（`lib/themes.js` 内核 + 测试）。
