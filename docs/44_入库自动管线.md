# 入库自动管线：原文解析 → 七段卡 → 精读（v0.12.0）

> 目标：文献入库后不再需要手动点三次，后台按顺序完成**原文解析、七段卡、精读**。
> 手动入口保留：论文行「补全」、`POST /api/litkb/ingest`。

| 项 | 内容 |
|---|---|
| 版本 | v0.12.0 |
| 触发 | 本地 PDF 导入、链接 / DOI 导入成功后自动入队 |
| 顺序 | 原文解析 → 七段卡 → 精读 |
| 默认 | 开启；设置 →「入库自动化」可关闭 |
| 并发 | 整条管线串行（一篇完成再下一篇） |
| 状态 | 内存任务；DSH 重启后不续跑，可手动「补全」 |

---

## 1. 用户看到什么

### 1.1 导入后

- 导入成功提示变为「已导入，正在自动处理」；
- 论文库顶部出现自动处理条：

```text
● 自动处理《论文标题》
  原文解析 … · 七段卡 · 精读 ·
  另 2 篇排队                        查看
```

- 每一步完成会更新为 `✓`；跳过为 `–`，失败为 `!`；
- 全部完成后提示「自动处理完成」或「自动处理部分完成」，论文列表刷新；
- 精读完成且论文状态仍是「待读」时，自动改为「精读」。

### 1.2 手动补全

论文行 hover / 选中后右侧新增 **「补全」**：

- 对旧论文、自动处理失败、或中途重启的论文使用；
- 已存在的步骤自动跳过：有解析稿不重跑解析，有七段卡不重生成，有精读不重生成；
- 只补齐缺失的步骤。

### 1.3 设置

设置 →「入库自动化」：

```text
[✓] 入库后自动完成原文解析、七段卡与精读
后台串行执行：原文解析 → 七段卡 → 精读。没有可用模型时只完成原文解析，
卡片与精读跳过；七段卡与精读会调用模型。
```

关闭后，导入只完成入库与基础文本抽取，不启动管线；仍可手动「补全」。

## 2. 管线语义

### 2.1 步骤

| 步骤 | 实现 | 依赖 | 超时 |
|---|---|---|---|
| `blocks` 原文解析 | `ensureBlocks`：PaddleOCR 可用则用，否则 pdf.js 兜底 | PDF | 30 分钟 |
| `card` 七段卡 | `startCardJob` → `generateCard` | 模型 + 文本/版面块 | 15 分钟 |
| `deepread` 精读 | `startDeepJob` → `buildDeepRead` | 模型 + 七段卡 | 15 分钟 |

已有产物直接记为 `done`，不重复调用模型 / OCR。

### 2.2 降级

| 情况 | 结果 |
|---|---|
| 宿主没有模型服务 / 未选默认模型 | `blocks` 正常；`card`/`deepread` 标记 `skipped`，整体 `partial` |
| 原文解析失败 | `card`/`deepread` 仍尝试（卡片可用 pdftext 兜底）；整体按完成数标记 |
| 七段卡失败 | `deepread` 标记 `skipped`，原因「七段卡未完成」 |
| 某步超时 | 该步 `failed`，继续后续可执行的步骤 |
| 全部完成 | `done` |
| 一项都没完成 | `failed` |

### 2.3 状态更新

```text
partial：至少一项完成，但不是三项
failed ：一项都没完成
done   ：三项都完成
```

`deepread` 完成后：

- 读取最新索引；
- 仅当论文状态是「待读」时改为「精读」；
- 重写卡片 Markdown，使列表与卡片页状态一致；
- 不覆盖用户手动设置的状态。

## 3. 接口

### 3.1 查询 / 手动触发

```http
GET  /api/litkb/ingest            # 最近 20 条
GET  /api/litkb/ingest?id=p-...   # 单篇（没有任务返回 job:null）
POST /api/litkb/ingest            # { "id": "p-..." } 手动补全
```

POST 返回 `202`：

```json
{
  "ok": true,
  "job": {
    "id": "p-7ac0d596",
    "paperId": "p-7ac0d596",
    "title": "Automatic ingest test",
    "status": "queued",
    "step": "排队中",
    "steps": {
      "blocks": { "status": "queued", "message": "" },
      "card": { "status": "queued", "message": "" },
      "deepread": { "status": "queued", "message": "" }
    },
    "startedAt": "2026-11-10T02:22:44.603Z",
    "finishedAt": null,
    "error": null
  }
}
```

完成示例（无模型环境）：

```json
{
  "status": "partial",
  "step": "部分完成（1/3）",
  "steps": {
    "blocks": { "status": "done", "message": "解析器 pdfjs-text@1" },
    "card": { "status": "skipped", "message": "宿主未提供模型服务" },
    "deepread": { "status": "skipped", "message": "宿主未提供模型服务" }
  }
}
```

### 3.2 导入响应

`POST /import`、`POST /import/link` 成功后多一个字段：

```json
{ "ok": true, "paper": { ... }, "ingest": { "id": "p-...", "status": "queued", ... } }
```

自动处理关闭时为 `null`。

### 3.3 设置

`GET /api/litkb/settings` 返回 `settings.autoIngest`；`POST` 可写：

```json
{ "autoIngest": false }
```

## 5. 边界

- 任务只在内存：DSH 完全重启后丢失进度；已落盘的步骤不会丢，点「补全」继续；
- 不自动建链：入库后只做解析、卡片、精读，建链仍需「自动建链 / 审核」；
- 不自动翻译、不自动生成研究、不自动写文稿；
- 无模型时不会伪造卡片/精读，只做解析并明确标记跳过；
- 管线串行：一批 5 篇会排队，不会同时调用 5 次模型；
- 30 分钟解析超时后，后台解析可能仍在跑；稍后点「补全」会复用已生成的解析稿。

## 6. 验收

1. 设置确认「入库后自动完成…」为开；
2. 导入 1 篇 PDF：出现「已导入，正在自动处理」与顶部处理条；
3. 等待：原文解析 `✓` → 七段卡 `✓` → 精读 `✓`，提示「自动处理完成」；
4. 打开论文：七段卡、精读、原文解析三个页签都有内容；
5. 关闭自动处理后导入：不再出现处理条，仅入库；
6. 对旧论文点「补全」：只补缺失步骤；
7. 无模型环境导入：解析完成，卡片/精读显示跳过，整体「部分完成」。
